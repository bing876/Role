# ADR-0009 · 按用户密文模型配置、单一出口与真模型评测

- 状态：接受（2026-09-27，完模式片④）

## 背景

旧程序仅从进程环境变量读取 DeepSeek key，`modelRouter.ts` 已按任务类型选模型，`llm.ts:llmFetch` 是所有模型请求出口。设置抽屉原先不能让登录用户配置模型；新配置若错误回退全局 key，会让用户以为已换模型却仍用共享模型，坏密文还会绕过安全边界。用户要求可配、密钥加密落本机，以及路由/委派/记忆/技能各 5 题的真实准确率报告；本沙箱没有可用 DeepSeek key，不能用桩伪造数字。

## 决定

1. 本地模型行复用现有 `plugin_configs(user_id,plugin_id='model',config_enc)`；`JsonCipher` AES-256-GCM 加密**整份** provider/baseUrl/model/apiKey，不另建明文列，也不把 key 放进 Electron `WorkbenchSettings`、localStorage 或日志。GET/POST 仅回打码 `ModelConfigView`。新配置默认 DeepSeek `deepseek-flash`；未保存本地行的旧部署仍按原 env 路由，保留 `DEEPSEEK_MODEL` 的现有默认和总开关语义。
2. 明确传入用户号的 `llmFetch` 每次从 DB 解密一次（进程 lookup 只保存 pool/cipher 引用，不缓存任何账号 key）；本地行优先覆盖 key/baseUrl/model，**只有无行**才按 env 任务路由。密文损坏、数据库不可读、查询器缺失：拒绝，不回落 env。主循环、聊天、路由、临时工、记忆抽取/卫生必须传当前账号。无 userId 的旧独立单测保留 env 行为。
3. API 地址公网只能 HTTPS、本机回环才可 HTTP；不接受 URL 凭据、query/fragment，不跟重定向。更换供应商或 baseUrl 须提交新 key，避免把旧供应商 key 交给新端点；遮罩串、mock 串不可保存。测试端点用同一生产 llmFetch，响应限 1MB，超时 15s；模拟 key 不记为真模型已连通。
4. `evals/model-20.mts` 固定 20 题（四类各五）：路由直接用生产 `semanticRoutePrompt`，委派与技能只把**生产工具 schema**提供给模型（不调用 executor，避免评测写数据/自动发送），记忆用生产 `EXTRACT_PROMPT` 和落库前敏感/工作规则过滤。`eval:model:live` 只允许真 key 到官方 DeepSeek HTTPS，逐题预测/标准与分组/总体准确率；缺 key、上游失败、少题 => NOT RUN/PARTIAL、非零退出、**不输出准确率**。离线 HTTP 桩只验评分器/客户端接线，不是模型精度。
5. 前端只在现有设置抽屉内添模型卡，不增每轮模型选择器、不改 webview 祖先链；通过 `features/model/index.ts` 和 `shared/api.ts` 访问鉴权端点。浏览器直测代理 `/model`，不调用客户端 localhost。

参考：DeepSeek 官方 Chat Completions `POST https://api.deepseek.com/chat/completions`、`response_format:{type:'json_object'}` 和工具调用：https://api-docs.deepseek.com/api/create-chat-completion；模型列表 `deepseek-flash`/`deepseek-v4-pro`：https://api-docs.deepseek.com/quick_start/pricing 。旧 env 默认为 deepseek-chat 是既有兼容行为，不把官方新列表误写成“旧别名肯定仍可用”；需要真机测旧账号的真实兼容性。

## 后果

- 同一进程通常只运行一个 Fastify app（`buildApp` 安装 lookup）；测试在真库里校验两账号及坏密文。个人设置每次发请求增加一次本地 DB 查询；目前不在内存缓存明文是安全优先的取舍。
- 显式覆盖一个 model 会让该用户的各任务统一走此 model；未设置的老账号仍可通过 env 按任务路由。若将来给用户开放逐任务模型配置，应新增字段/迁移及单独评测，不暗改本规则。
- 无 DeepSeek 凭据和公网访问时，只能报告离线协议/判分通过，**不能**报告 20 题真实准确率；发布前需要在联网机器执行 `npm run eval:model:live` 并记录原始逐题输出。

## 备选与否因

- 每次对话选模型、把 key 放主进程 JSON/localStorage：增加管理负担且以明文持久化，拒绝。
- 坏密文自动回 env：隐藏故障、可能跨账号用共享 key，拒绝。
- 用 mock 回答凑出“20/20 真实准确率”：测到的是预设答案而非模型，拒绝。
- 让评测脚本实际执行委派/教技能：会写生产数据、触发自动发送，与只测模型决策和用户限制冲突，拒绝。
