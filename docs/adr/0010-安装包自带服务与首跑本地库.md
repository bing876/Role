# ADR-0010 · 安装包自带后端、持久化本地库与一次性引导

- 状态：接受（2026-09-27，完模式片⑤）

## 背景

旧 electron-builder 配置只装入桌面端 `dist`/`dist-electron`：已安装应用靠扫描开发仓库找服务端，靠 `~/workbuddy-ai/pg2` 找 PostgreSQL；全新 Windows/macOS 机器两者都不存在。`package:dir` 即使完成也不能独立登录。旧 `DATABASE_URL`/`DATA_KEY`/`JWT_SECRET`/`PHONE_PEPPER` 必须显式提供，这是防止弱密钥的安全闸，不能为“首跑顺滑”削弱。旧开发态的 PG 守护与账号体系须原样保留。

## 决定

1. 生产安装包保留 Electron 主进程 + 独立服务端进程的边界；electron-builder `extraResources/server` 装入**已构建** `apps/server/dist`、独立且有锁文件的生产依赖、编译后的 shared（含 PGlite WASM）。从 `process.resourcesPath` 定位，不扫描开发仓库、不依赖系统 Node/Docker/PG/tsx；Electron 自带 `ELECTRON_RUN_AS_NODE=1` 起服务端（该 fuse 维持默认 enabled）。开发态保留既有便携 PG + 服务端探活路径。
2. 仅打包态首跑在 Electron `app.getPath('userData')` 下创建本地 PGlite 目录及版本化 `local-runtime.json`；使用加密学随机数生成互不相同的 DATA_KEY/JWT_SECRET/PHONE_PEPPER，密钥文件 Unix `0600`（目录 `0700`，Windows 用当前用户 profile ACL），数据库/密钥只在 userData，**绝不在应用包、仓库、数据库明文列、日志**。后续只读原文件，损坏/缺字段/权限过宽时 fail-closed，不重生成密钥（否则旧密文将不可恢复）。PGlite 沿用生产 `db.ts:makePool()`/`migrate()`；不迁移或覆盖开发者已有 PG。
3. 打包态设 `NODE_ENV=production`、`SMS_MOCK=0`、`ENABLE_DEV_MOCK_LLM=0`，并拒绝继承环境中形如 `mock` / `mock:*` 的模型 key；后端只绑回环；不把模拟短信或模型假答当真实能力。首跑 `GET /auth/onboarding` 仅返回 `{available}`；一次性 `POST /auth/onboarding` 要求打包进程每次启动生成、只通过主进程 IPC→服务端传输的高熵 bootstrap secret + 用户密码，服务器只接受用户表为空且开启本地模式时创建一个带 scrypt 密码的 XYZ 账号、默认项目、小助。已有账号或凭据错误拒绝；创建后走原 XYZ+密码登录。渲染层只新增初次引导卡（提示本机存储、设密码/记住 XYZ、在现有设置里填模型 key），不自动发送/执行任务、不把密码写 localStorage，原登录页不移除。缺真实模型 key 时明确让用户配置，绝不假答。
4. Windows NSIS `.exe`、macOS DMG `.dmg` 只在对应目标操作系统构建/签名/启动验证；Linux 可构建本平台 `--dir` 检查资源与真实 server 启动，不能把 Linux 目录包当作 Win/mac 安装验收。`package:dir` 用同一先构建 shared/server/desktop + staging 流程；完整验收需断包内文件、安装目录启动、首跑建库+引导、重启保留登录数据。任何外部 8787 冲突不能静默连错数据库或杀用户服务；打包态 renderer 忽略旧 `workbench.apiBase`，只有主进程报告自家子进程就绪时才发认证请求（含 F5 保存的 JWT），首跑 UI 在端口被占时不探测他人的 /health。开发态自定义地址仍兼容。

参考：electron-builder v26 `extraResources` 位于 `resources/`、`--dir` 仅生成 unpacked 目录：https://www.electron.build/v26/docs/contents/ 与 https://www.electron.build/v26/docs/cli/；Electron fuse `RunAsNode` 默认开启：https://www.electronjs.org/docs/latest/tutorial/fuses 。

## 后果

- 安装包将增大（PGlite WASM、服务端依赖、Electron 运行时）；预备目录被 `.gitignore` 排除；stage 只含生产依赖，不含 `.env`、源代码或测试凭据。
- 打包端第一次启动可能等几秒建表；登录 UI 保留“检查中/真登录页”两态，需等 `/health.db='up'` 与 `/auth/onboarding` 就绪才能启用首次引导。子进程死亡时 supervisor 只重启**自家**进程；密钥损坏不自动覆盖。
- Mac DMG 签名/公证、Windows SmartScreen/代码签名、目标系统 Electron/WebContentsView/CDP 仍需对应真机逐项验收；Linux 沙箱若下载受阻不宣称打包通过。

## 备选与否因

- 随安装包固定一套密钥/包含 `.env`：所有设备共享钥匙、明文入包，拒绝。
- 首次启动启用 `SMS_MOCK=1` 并展示验证码：上线包假装拥有真实短信认证、同网段可滥用，拒绝。
- 让用户先装 Docker/PostgreSQL/Node 或扫描开发仓库：不满足首跑自动建库，拒绝。
- 突然把后台全搬进 Electron 主进程：破坏现有职责与故障隔离，超出小片范围，拒绝。
