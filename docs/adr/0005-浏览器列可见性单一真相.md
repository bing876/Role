# ADR-0005 · 浏览器列可见性的单一真相(view → 列)

- 状态:已接受(2026-09-26,用户「任务1 浏览器空白」指令后,先诊断复现、再改)
- 依据纪律:`docs/工程纪律.md` #1(重要决策写 ADR)、#2(先规格后代码)、#3(先列失败模式)、#4(不熟先查源码)
- 相关:`docs/adr/0002-webview迁WebContentsView.md`(页宿主)、`docs/产品交互规格.md` C2(第四列)

## 背景

用户报:**「启动后发『打开抖音』,右侧浏览器面板空白(页已创建、已加载,但没显示)」。**

真机复现(2026-09-26,dev 桌面端 + CDP 直插渲染层,见「证据」节):在聊天框发「打开抖音」后 —

- 标签页建了(`douyin.com`)、guest 真加载了(`/json/list` 里有 `https://www.douyin.com/`)、AI 真开始在它上面驾驶;
- 但 `.browserLayer` 的 class 是 **`browserLayer browserLayer--hidden`** —— 第四列被
  `transform: translateX(calc(100% + 16px))` **整体移出视野**(实测 `getBoundingClientRect().x = 1180`,
  而窗口 `innerWidth = 1164`)。
- 于是「页已创建、已加载,却看不见」——症状与用户描述逐字一致。

**根因(两条独立状态必须一致,但没人保证一致)**:

第四列的可见性在代码里由**两个 state 的与**决定:

```
App.tsx: browser.view === 'embed' ? 层--embed
       : col.colOpen && browser.view === 'fullscreen' ? col.layerClass   ← 要两个都真
       : 'browserLayer browserLayer--hidden'
```

- `browser.view`(在 `apps/desktop/src/browser/`,「要不要给人看」的语义);
- `col.colOpen`(在 `apps/desktop/src/app/useBrowserColumn.ts`,外壳侧的列开关)。

`openUrl()` 里**显式**写了 `setView('fullscreen')`,它自己的注释也写着「openUrl 的调用方都是
『用户明确要看浏览器』」。但**没有任何人把这件事告诉外壳的列** —— 除了三个触发点自己顺手调
`col.openColumn()`(会话链接 / 「🌐 启用」/ 欢迎卡按钮)。**聊天里说「打开 XX」这条主路径漏了**:
`features/chat/useChat.ts` 的 `if (openUrl) { await browser.openUrl(...) }` 只开页、不碰列。

对照真机证据:CDP 直调 `window.workbench.openBrowser(...)`(走 `openFromMain` → `openUrl`)之后
层同样是 `--hidden` —— 说明这不是 useChat 一处漏,而是**「view 说要看、列没开」这个状态本身没有守卫**。

## 决定

1. **列的可见性以 `browser.view` 为单一真相**:在 App 里加一条同步 effect ——
   `browser.view === 'fullscreen'` ⇒ `col.openColumn()`。
   即:**任何让 `view` 变成 `fullscreen` 的路径(今天 4 条、将来更多)都自动把列打开**,不再依赖
   每个触发点自己记得调 `openColumn()`。
2. **不动 `browser/` 一行**:`openUrl` 的 `setView('fullscreen')` 是**正确**的既有语义(它就是
   「要给人看」),缺的是外壳侧的跟随。分层规则(feature 不许反向依赖 app)也要求这件事在外壳做。
3. **`openFromPage`(内嵌页里 `target=_blank` / AI 自己开页)语义不变**:它**不碰 `view`**,
   所以列该开就开着、该关就关着 —— 「AI 开页不抢用户视线」这条第 28 步拍板原样保留。
4. **既有验收口径修正一处**:`app-shell-smoke` 里「'open' 事件 = 后台开页(层必须 `--hidden`)」
   这条断言的前提**与生产码矛盾**(`openFromMain` → `openUrl` → `setView('fullscreen')`)。
   按「改标准 = 改断言」纪律,把该断言改成新口径:**主进程 `open` = 要给人看 ⇒ 层必须可见**,
   并同时断言「可见 ≠ 新建视图」(视图仍是同一个、`visible:true`)。
   (该通道今天只有 `workbench:open` 一个来源,渲染层零调用点;口径按代码实际语义对齐。)

## 后果

**正面**
- 「打开 XX」在任何入口(聊天 / 会话链接 / ＋ / 启用 / 主进程 open)之后**都看得见页**。
- 这类「两个 state 必须同进同退」的 bug 从「靠每个调用点记得」变成「由一条 effect 兜住」;
  将来新增开页入口不会再踩。

**负面 / 取舍(如实登记)**
- 多一条 effect(每次 `view` 变化跑一次),成本可忽略;
- `view === 'fullscreen'` 时列**必然**打开 —— 如果将来要做「后台全屏但列收起」这种组合,
  得先改这条 effect(现在是显式不允许的状态)。
- 真机上的**视觉确认**仍是最后关口:本机沙箱能开 Electron 真窗口(已用 `desktopCapturer` 抓图
  验证过原生视图确实贴到占位区),所以本 ADR 的真机证据是**截图**而非「无法覆盖」。

## 备选与否因

| 方案 | 结论 |
|---|---|
| **A. 在 `useChat` 里补一句 `col.openColumn()`** | 治标:`openFromMain` 等其它路径照样漏;而且 `useChat` 拿不到 `col`(它只依赖 `browser/` 的接口),要么加参数穿透、要么反向依赖 app 层。**否** |
| **B. 把 `openColumn()` 塞进 `openUrl` 内部** | `browser/` 是 feature 层,**不许**依赖外壳的列状态(分层规则 + 它自己的文件头写明「`browser/` 一行不动」)。**否** |
| **C. 删掉 `colOpen`,列的可见性完全由 `view` 推导** | 更彻底,但会动 `useBrowserColumn` 的对外契约与 `--overlay`/拖动/`app--col` 三处调用点,回归面比收益大。**否**(留作后续重构候选) |
| **D. 把 `--hidden` 改成 `display:none` 之类** | 直接破红线(隐藏 ≠ 卸载、驾驶坐标依赖真实几何)。**否** |

## 失败模式表(doubt-driven:动手前列,验收逐行盖)

| # | 会怎么坏 | 验收怎么盖 |
|---|---|---|
| F1 | effect 没兜住(写成依赖 `col.colOpen` / 条件写错)→ 层还是 `--hidden` | 新增断言:发「打开 XX」后层**不含** `--hidden`;**反证**:摘掉 effect → 必红 |
| F2 | 修过头:列变成「永远打开」,「💬 对话」再也收不起来 | 断言:点「💬 对话」后层**必须**带 `--hidden`(既有断言保留) |
| F3 | 「AI 自己开页」被误伤,开始抢用户视线 | 断言:`openFromPage`(opentab)后层状态**不变**(不因它而打开) |
| F4 | 可见性变了但视图没跟着(rect 没重发)→ 列亮了页仍空 | 真机:发「打开抖音」后抓窗口截图,页必须可见;CDP 侧断言 `view-rect` 的 `visible:true` |
| F5 | 隐藏 ≠ 卸载被破坏(顺手改成销毁) | 既有断言 + 反证 C1–C5 / R1–R6 全红才算过 |
| F6 | 改了标准却把断言「调到绿」 | 该断言的新口径写进本 ADR 与验收报告;反证必须让它红 |

## 证据(2026-09-26,真机)

1. **机制层(排除嫌疑)**:用**真实的** `apps/desktop/dist-electron/view-host.js` 起 Electron 44.4.5,
   create → rect(744,64,420,657) → `getBounds()` 与 `getVisible()` 逐字吻合,
   `desktopCapturer` 抓窗口截图**肉眼可见 example.com 正好画在右侧占位区** ⇒ 原生视图机制本身没问题。
2. **真机复现**:dev 桌面端(`vite` + `electron . --remote-debugging-port=9222`)登录后,
   在输入框发「打开抖音」→ 标签 `douyin.com` 出现、guest target `https://www.douyin.com/` 出现、
   AI 开始驾驶,**但 `.browserLayer` 全程 `browserLayer--hidden`**(x=1180 > innerWidth=1164)。
3. **同因异路**:CDP 直调 `window.workbench.openBrowser('https://www.douyin.com')` → 同样 `--hidden`。
