# ADR-0006 · 三层状态合一：唯一真相 = 服务端任务状态

- 状态:已接受(2026-09-27,用户拍板「B2 三层状态合一条、唯一真相=服务端任务状态」)
- 依据纪律:`docs/工程纪律.md` #1(重要决策写 ADR)/ #2(先规格后代码)/ #3(先列失败模式)
- 相关:`docs/产品交互规格.md` C3(无感)/ C9(执行中与最终回答)、`docs/adr/0005-浏览器列可见性单一真相.md`

## 背景

同一个"AI 现在在干什么"在界面上**有三处**各画一遍，各自的判据还不一样：

| 位置 | 组件 / class | 现在的判据（**客户端**） |
|---|---|---|
| 输入框上方一行状态 | `.runStatus`（`.runStatus--paused`） | `runningLoopId && streaming` → 执行中；`awaitResume && awaitResumeAgent === curAgentId` → 已暂停 |
| 浏览器层顶部的可见度条 | `.computerVisibility__bar` | `computerVisibility`（按智能体存档的档位）+ `visAgent?.status` + 最后一条步摘要 |
| 聊天区顶部的会话状态行 | `.taskState` | `curState`（`conversations.current_task` / `keepalive` / `browser_confirmed`）+ `task.phase` |

**问题不是"重复"，是"判据不同"** ⇒ 三处可以同时给出互相矛盾的画面。已经踩到的实例：

- 发「停」后服务端那条循环是**挂起**（可「继续」），但 `.runStatus` 的判据 `streaming` 仍是 true（SSE 没关）
  ⇒ 靠 `pausedHere` 单独兜住；任何**新加**的按 `streaming` 判断"正在干活"的地方都会踩同一个坑（UX 收尾片 A① 的注释里记了这条不变量）。
- `.taskState` 读的是**会话级** `current_task`（服务端），`.runStatus` 读的是**客户端在途值**（`runningLoopId`）——
  两者在"刚发车但服务端还没回 loopId""循环已结束但 SSE 还没收尾"这类窗口里必然各说各话。
- 可见度条的档位是**用户偏好**（按智能体存档），却和"AI 在不在跑"挤在同一条上，读的人分不清哪个是真状态。

## 决定

> ★ 本片范围（用户 2026-09-27 拍板）：**本片只落口径（这份 ADR）**。
>   代码分片见「决定 4」，**不在本片执行** —— 写 ADR 是为了让下一片有据可依，不是先改代码后补文档。

> ★ 本片范围（用户 2026-09-27 拍板）：**本片只落口径（这份 ADR）**。
>   代码分片见「决定 4」，**不在本片执行** —— 写 ADR 是为了让下一片有据可依，不是先改代码后补文档。

1. **唯一真相 = 服务端任务状态**。权威字段（按优先级）：
   - `GET /agent/loop/*` 与 `/agent/task/current` 的回执（**任务态**：`phase` / `summary` / `paused`）；
   - `conversations.current_task` / `keepalive` / `browser_confirmed`（**会话态**，服务端为准则）；
   - `agents.status`（`idle/thinking/working/waiting/blocked/done`，头像即状态那套）；
   - `/health` 的 `runningLoops` / `liveLoops`（**全局兜底**：客户端与服务端分歧时的最终裁决）。
2. **客户端瞬时态只作"在途乐观值"**：`streaming` / `runningLoopId` / `awaitResume` / `drivingIds` 允许先动（用户点了就该立刻有反馈），
   但必须**在拿到服务端回执后收敛**，且**只允许一个方向**：服务端说"没在跑" ⇒ 界面必须回非执行态；
   服务端说"在跑" ⇒ 界面回执行态。**不允许**客户端值覆盖服务端的"不在跑"。
3. **派生链单向**：服务端状态 → `curState`（拉取 + 既有事件广播）→ **一处派生**出各处的**形态**：
   - `.runStatus` 只读「任务态 + 会话态」派生的 `runBarMode`（`running | paused | null`）；
   - `.computerVisibility__bar` 只画**用户偏好档位**（可见度），**不再兼画"在不在跑"**（那是 `.runStatus` 的活）；
   - `.taskState` 只画**会话态**（保活/当前任务/已同意用浏览器），与"执行中"无关的内容留在它这儿。
   ⇒ 一句话：**同一个事实只画一次；同一处 UI 只允许读一个派生源**（与 ADR-0005 同一条原则）。
4. **代码分片（下一片执行，不在本片）**：只落"口径 + 派生的唯一入口"，不重写三块 UI：把三处的判据收敛到 App 里**一处派生函数**
   （`deriveRunFacts(...)` 之类，输入 = 服务端状态 + 在途乐观值，输出 = `{ runBarMode, visHint, sessionHint }`），
   三处 JSX 只消费它，不再各自判一遍。**分片**：先落口径与本 ADR + 把 `.runStatus`/`.taskState` 接上同一派生源；
   可见度条剥离"在不在跑"放下一片（它涉及用户偏好存档，动它会牵到 `computer_visibility` 那条既有验收）。

## 后果

**正面**
- 三处不可能再互相矛盾：**只有一个地方在算"现在是什么状态"**。
- 收敛方向被写死（服务端优先），"挂起时 `streaming` 仍为 true"这类**客户端在途值与真相不一致**的窗口，
  自动被服务端的"不在跑"覆盖 ⇒ 以后新增 UI 不会再各判一次。
- `.computerVisibility__bar` 回归单一职责（只管可见度偏好），用户不再需要在一行里分辨两种含义。

**负面 / 取舍（如实登记）**
- 需要一次**异步收敛**（发车瞬间到服务端回执之间，界面仍是乐观值）——这段窗口是**有意的**，
  否则用户点一下要等一个来回才有反馈；代价是"极短窗口内界面可能比真相乐观一点点"。
- 服务端**没有**"这条循环现在是否暂停"的显式字段（挂起是 `/agent/loop/pause` 的副作用）⇒
  本片先用"收到 pause 回执即视为挂起"，并把「服务端补一个 `loop.paused` 字段」记为**待办**（见缺口）。
- `.taskState` 与 `.runStatus` 合并成同一派生源后，两者的**呈现位置不变**（一个在聊天区顶、一个在输入框上方），
  只是判据统一 —— 视觉上不减少元素，减少的是"判据份数"。

## 失败模式表（doubt-driven：口径落地会怎么坏，怎么验）

| # | 会怎么坏 | 怎么验 |
|---|---|---|
| F1 | 派生函数只被其中一处消费（另一处仍自己判）⇒ 又回到"三份判据" | 结构闸：三处 JSX 里**不允许**再出现裸 `streaming && runningLoopId` 这类组合判断（静态断言）；反证：把某处改回自判 ⇒ 红 |
| F2 | 服务端说"没在跑"但界面还在执行态（收敛没生效） | 逻辑验收：模拟"在途值在跑 + 服务端回执不在跑" ⇒ 必须回非执行态；反证：去掉服务端优先的收敛 ⇒ 红 |
| F3 | 服务端说"在跑"但界面回非执行态（收敛方向写反） | 同上反向用例；反证：把优先级颠倒 ⇒ 红 |
| F4 | 可见度条被顺手剥掉用户偏好（档位丢了/不存档了） | 既有 `verify:visibility`（40 断言）必须照绿；反证：档位不再落库 ⇒ 既有反证照旧咬 |
| F5 | "服务端不可达"时界面卡在乐观态（断网 → 永远"执行中"） | 验收：服务端回执超时/失败 ⇒ 降级为"以最后一次已知的服务端状态为准"，**不新增**执行态 |

## 备选与否因

| 方案 | 结论 |
|---|---|
| **A. 保留三处各自判、只统一字段名** | 治标：判据仍是三份，矛盾还会长出来。**否** |
| **B. 把三块 UI 合并成一条状态条** | 会把"用户偏好（可见度档）"与"任务态"塞进同一行 —— 用户更难看懂，且改的是信息架构不是口径。**否**（本 ADR 只"合一判据"，不合并元素） |
| **C. 全部改由服务端推送（客户端零判据）** | 最彻底，但发车瞬间没有反馈（要等一个来回），且离线时界面什么都不显示。**否**（保留"乐观值 + 收敛"） |
| **D. 唯一真相 = 客户端（服务端只作日志）** | 与服务端才是任务/循环的持有者这一事实冲突（重启恢复、多端一致性都要靠服务端）。**否** |

## 缺口（本片不修，登记在案）

1. 服务端**没有**显式的"这条循环当前是否挂起"字段 ⇒ 暂停态靠"收到 pause 回执"推断。建议下一片在
   `toolLoop`/`routes/loop.ts` 补 `paused: boolean`，并让它进 `/agent/task/current`。
2. `.taskState` 的 `curState` 是**拉取式**（`loadAgentState`），不是推送 ⇒ 它的新鲜度依赖调用点；
   本片不动它的拉取机制，只统一"谁派生谁"。
3. `computer_visibility` 撤档（`status` 档）时会不会顺带隐藏"AI 在跑"的信息：本片口径下**不会**
   （可见度只管看得见多少，任务态在 `.runStatus`）—— 但这条要在下一片真正剥离开时**真机复核**一次。
