# ADR-0012 · 单工作区、并列主智能体与统一运行事实

- 状态：已接受（2026-09-30，用户拍板；编号 0012，保留已有 ADR-0007）
- 关联：`docs/adr/0006-三层状态合一-唯一真相.md`、`docs/产品交互规格.md`、`docs/前端接入契约.md`
- 范围：去项目化的**用户界面**、默认工作区与运行事实状态片；不删除项目数据、路由、隔离机制，不改已有账号的历史数据。

## 背景

左栏目前有可切换、可新建项目的面板；登录返回上次激活的项目。用户本来只想直接与智能体对话，却要先理解项目。光隐藏控件、继续使用上次激活的项目，会使左栏与服务端创建智能体或上传资料的归属不一致。默认项目、协同、知识库和浏览器分区依赖项目数据行，隐藏 UI 不等于删库。

`App.tsx` 的六态头像、运行状态行与 `ComputerVisibility` 各自从 `status`、`streaming`、任务与休眠标记解释“它在干嘛”。ADR-0006 已要求服务端状态为权威，但前端仍缺唯一派生入口；手动暂停后 SSE 仍可能保持 streaming。

## 决定

1. **用户只见一个工作区**：现有属于该用户的 `is_default=true` 项目是默认工作区的内部实现。每次登录/恢复先读 `/projects`；若当前项目不是默认项目，先用已有 `/projects/:id/activate` 同步服务端，再按默认项目 ID 拉智能体、资料与任务。不能只改前端选中值。无默认行、请求或激活失败时不猜其他项目、不加载旧项目资料，显示可见错误；不隐式创建项目或迁移旧行。
2. **项目与团队是实现细节**：左栏不再有新增/切换项目入口，也不把“搭团队”作为新账号首进的自动提议。小助仍是默认工作区可立即对话的主入口；在小助会话说“创建 XX”，经既有权限闸直接在该工作区新增一名**并列一级智能体**，不创建项目或团队。非小助创建请求沿用现有转交小助的安全语义，不能放宽 `POST /agents` 鉴权。历史消息不删除；旧团队提议只作为普通历史文字展示，不再从历史记录生成快捷建人按钮。协同卡、旧项目行与 API、项目归属与浏览器分区继续留作兼容，但不从新 UI 暴露管理入口。
3. **运行事实一处解释**：纯函数 `deriveRunFacts(...)` 输入服务端智能体/任务/会话状态及客户端在途信号，输出头像、运行条与“它在干嘛”的同一份事实；可见度条消费同一派生提示，不另建状态词典。服务端已知状态优先，客户端在途信号只补未确认窗口；本地暂停/人工介入不得被尚未结束的 streaming 覆盖。头像只画**空闲、执行、需你处理、出错**四态；`thinking` 并入执行头像、`sleeping` 并入空闲头像，区分只在“它在干嘛”细节行。保留服务端历史状态枚举和线上数据协议。
4. **小片边界**：本片落实默认工作区、移除项目 UI、新账号不自动提团队、既有对话建人的并列语义及 `deriveRunFacts` 消费接线。保留旧项目 API 和团队协同能力；不删数据库行、不改写历史消息、不跨项目迁移、不重做浏览器视图。上传接口允许桌面显式提供经鉴权的项目 ID，以防旧客户端切换 `current_project_id` 后上传落到旧项目；不带参数的旧客户端行为保留。

## 后果

- 首进无需选择项目即可见小助；一句话建人后名单增一位同级智能体、项目数不变。多个同级智能体继续共用默认工作区的登录态分区，旧项目之间仍隔离。
- 老账号若上次使用非默认项目，登录会多一次服务端激活。缺默认项目/激活失败时宁可报错，也不让服务端写入别处；上传在未确认默认工作区时须拒绝。
- 旧项目行/API 不删除，UI 隐藏不是鉴权；旧客户端的归属检查必须继续生效。历史“搭团队”消息保留为普通文字。
- ADR-0006 的服务端任务状态优先不变；任务 API 未提供完整暂停字段时，已获回执的本地暂停是有界在途事实。旧轮主进程镜像仍停在 `pausedBy=user` 时，**同时证明镜像接收时见过旧 `statusLoopId`**、已确认一个不同的新 SSE 循环、且本地无暂停回执，才可盖过旧镜像；缺任一证据就等下一次主进程广播，不凭旧名单猜当轮镜像过期。当前本地暂停或 `pausedBy=agent` 不得被盖过。可见度档位是偏好，不用来猜任务是否运行。
- 主进程不点名页的 `getTaskState()` 是聚合快照：带 `wcId` 的通过页反查 owner；缺 `wcId` 的旧广播在**接收时**绑定当时的智能体，不能因切人重新归属。页归属或登录态不明时不将暂停/失败涂到任何人的头像。步摘要、页面标题同样不跨人复用。
- `deriveRunFacts` 只改客户端展示映射，`AgentView.status`、`TaskState`、`ConversationStateView` 的线上协议不变。左栏细节/头像提示/可见度提示是同一句“它在干嘛”；会话状态行仅显示保活、当前任务等会话元数据，运行条由同一事实给出暂停/执行文案。

## 标准 / 验收 / 反证

| 标准 | 正向验收 | 反证：故意退回时必须红 |
|---|---|---|
| 首进默认工作区直接见小助 | 旧 current 指向非默认时，先 activate 默认，再拉名单/资料；激活失败或缺默认行不读旧项目 | 删默认选择/跳过 activate/拿旧项目兜底 → 错归属断言红 |
| 左栏无项目入口、旧数据/API 保留 | 挂整个 App 检查无新增/切换控件；真服务端测旧项目 API | 把项目入口加回左栏 → DOM 断言红 |
| 一句话建并列智能体 | 小助真库创建后名单增一、项目数不变；非小助仍转交/拒越权 | 改成建项目/落入旧项目 → 真库断言红 |
| 新账号不自动提团队；旧历史保留 | 真库检查注册后无自动提议；历史提议仍可读但无快捷建按钮 | 恢复注册种子/按钮 → 用户可见断言红 |
| 状态单源、头像四态 | 逐态验证 `deriveRunFacts` 的头像/运行条/细节，暂停不被 streaming 覆盖；三处消费同一派生源 | 头像/可见度恢复本地第二份映射 → 结构或行为断言红 |
| 资料只写默认工作区 | 默认激活前/失败时禁用上传并在 hook 拒绝绕过；已激活则请求显式 `projectId`，服务端校验归属 | 去掉禁用/守卫/显式 ID/服务端归属校验 → 反证红 |

## 失败模式（实施前列出）

| 会怎么坏 | 防护 / 验证 |
|---|---|
| 只改 UI 未激活默认项目，新智能体或上传资料落入旧项目 | 先 activate 成功再拉名单；真库核对项目数、智能体和资料归属；失败不回退旧项目，上传按钮与 hook 双重拒绝。 |
| 快速切号或 `/projects` 响应晚到覆盖新账号 | 沿用 `sessionRef` token 守卫和既有晚到响应反证。 |
| 去掉项目控件时误删旧路由或分区白名单 | 保留 `/projects` 同步与服务端 API；跑既有隔离/兼容验收。 |
| 简化状态时把暂停或失败装成执行 | 逐态与任务优先级测试；故意恢复第二份判据必红。 |
| 停止首进提议时连带删了对话创建或历史消息 | 只停新账号种子；跑小助/非小助创建和旧消息验收，不碰历史表。 |

## 备选与否因

| 备选 | 否因 |
|---|---|
| 物理删除 projects 表、合并所有旧项目 | 破坏历史归属、分区与鉴权，迁移不可逆；本片只改用户心智和入口。 |
| 仅隐藏控件，沿用 currentProjectId | 老账号进入的仍是旧项目，违背默认工作区。 |
| 每建一个智能体自动新建项目或先搭团队 | 把用户刚去掉的管理成本带回来；并列一级智能体已由用户拍板。 |
| thinking/sleeping 仍占头像两态，各处继续维护词典 | 回到六态与状态双源；细节行足以表达。 |

## 已知边界

- 真库验收覆盖服务端、jsdom 覆盖整 App 的 DOM/请求；**不等于已在真实 Electron GUI 手测**。
- 旧账号已落库的“搭团队”历史消息继续可见；是否迁移历史内容**需用户拍板**，本片不擅删。
- 服务端循环缺完整暂停字段（ADR-0006 未完成项）；本片只保证前端单点派生并保留既有暂停语义。
