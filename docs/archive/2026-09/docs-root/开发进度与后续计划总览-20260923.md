## 0.5 ★ 计划是怎么组织的 & 我们现在在哪

这个项目的「计划」其实是**三条并行的轨道**，不是一条直线：

| 轨道 | 形态 | 进度 |
|---|---|---|
| **A · 功能主线（按「第 N 步」）** | 第 1 步 … 第 28 步，每步一份交付报告 | ✅ 到第 28 步 |
| **B · 能力阶段（阶段 0 → 1 → 2 → 3）** | 从 `docs/阶段0-Tool-Registry实施说明-20260922.md` 起头，每阶段一份「方案」 | ✅ 阶段 0 / 1 / 2；阶段 3 未立项 |
| **C · 质量与安全批次（R1–R4、P1/P2/P3）** | 审查报告 + 待办文档 | ⚠️ R1·R3 入基线；**R2·R4 有残留** |

### 「多智能体编排」在计划里的位置 —— **在，而且是轨道 B 的主体**

```
阶段 0  Tool Registry                  ✅ 已完成（181 断言）→ 留下 registerServerTool 扩展口
   ↓
阶段 1  临时工（spawn_workers）          ✅ 已完成
阶段 2  委派（delegate）+ 内部频道        ✅ 已完成
   ↓    阶段 1 + 阶段 2 合起来 = 「多智能体编排」，方案 S0–S10 全部交付（155 断言 / 0 失败）
```

> ★ 编排**不是「第 29 步」** —— 它不按步编号，而是独立的能力阶段批次。
> 所以问「在第几步」找不到答案；正确的问法是「**在哪个阶段的哪个位置**」。

| R7 | `pageState` 跨租户串扰 | 按 userId 隔离 |
| R8 | 模型挂死 90 秒零反馈 + 直接 `failed` 终态 | 中间态反馈 |

| R10 | 敏感等待永不自动恢复 | 超时自动回到可交互 |
