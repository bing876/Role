## 二、Agent（智能体）实现现状

### 1. 目前有几个 Agent？分别是什么名字、什么职责？

需要先澄清：本项目"Agent"一词指**两种不同层次**的东西：

**（A）产品层"智能体"（`agents` 表，多实例身份）** —— 不是自主 Agent，是"聊天身份 + 人设 + 独立记忆 + 独立会话 + 独立浏览器分区归属"：

| kind | 名字 | 职责 |
|---|---|---|
| `assistant` | 小助（每账号默认，不可删） | 默认聊天与驾驶员，可创建智能体（`canCreateAgents=true`） |
| `hen` | 母鸡（随每个新项目自动创建，不可删） | 项目级"母"智能体，可创建智能体 |
| `custom` | 用户"添加"新建（默认名"新智能体"，引导表确认人设后 `persona_status='ready'`） | 用户自定义分身，各自独立 conversation + 项目记忆，默认无建智能体权限 |

以上由 `apps/server/src/routes/agents.ts` 管理（`GET/POST /agents`、`POST /agents/:id/persona`、`DELETE /agents/:id`、`POST /agents/:id/tidy`）。它们**本身不含决策循环**，循环是下面 (B)。

**（B）执行层"驾驶员循环"（真正的 Agent Loop，手写，只有一套引擎，多路并发实例）**：

- 脑：`apps/server/src/toolLoop.ts`（`startLoop/advance/pauseLoop/resumeLoop` + `LOOP_SYSTEM_PROMPT` + `LOOP_TOOLS`）
- 手：`apps/desktop/electron/agent.ts`（`runToolLoop`）+ `driver.ts`（`drive()` CDP 执行）
- 并发模型：主进程 `main.ts` 的 `lanes: Map<wcId, Lane>` —— **一张内嵌页 = 一路**，多路真并行（默认上限 20 路，`maxConcurrentAgentTasks` 可调）。

### 3. Agent 之间如何调度 / 通信 / 协作？调度逻辑代码

**结论：智能体之间没有协作协议，也没有任务分解/委派。** 所谓"调度"只有两层含义：

1. **同一智能体的多路驾驶互不干扰**：靠 `wcId`（页）+ `agentId` 隔离。`/agent/loop/next` 每次校验"建循环时记的 agentId/wcId 与调用方自证必须一致"，否则 409（`routes/loop.ts`）：

```ts
const agentIdRaw = Number(b?.agentId);
if (session.agentId !== null && agentIdRaw !== session.agentId) {
  return errJson(reply, 409, `这个循环属于智能体 ${session.agentId}…`, { code: 'agent_mismatch' });
}
const wcIdRaw = Number(b?.wcId);
if (session.wcId !== null && wcIdRaw !== session.wcId) {
  return errJson(reply, 409, '这个循环只操作它自己那张页…', { code: 'page_mismatch' });
}
```

2. **同一页新指令覆盖旧指令（"最新指令优先"）**：`main.ts` 的 `startAgentLoop(wcId, goal, …)` —— 同 `wcId` 已有 lane 则 `prev.aborted = true` + 停掉服务端旧循环，别页 lane 完全不动。

渲染层靠 `emitAgent(payload, wcId)` 事件里的 `wcId` 把步骤/问话/结论落回发起的智能体聊天（`main.ts`）：

```ts
function emitAgent(payload: AgentEventPayload, wcId?: number): void {
  sendToMainWindow('workbench:browser:agent', JSON.stringify(wcId === undefined ? payload : { ...payload, wcId }));
}
```

### 4. 是否用了 Agent 框架？

**没有。纯手写调度逻辑。** 无 LangGraph / AutoGen / CrewAI / LangChain。循环、状态、并发、暂停恢复、重入锁全部手写（`toolLoop.ts` 服务端 + `agent.ts` 桌面侧 + `main.ts` Lane 管理）。

### 5. 决策循环怎么实现？（ReAct 还是别的）

**是"function-calling 版 ReAct"的手写变体，且是拉取式（服务端一次只推进一格，桌面 `for(;;)` 主动拉）**：

- 服务端 `advanceInner()`（`toolLoop.ts`）：喂回执 → 步数闸 → 调模型（带 `LOOP_TOOLS`）→ `sanitizeToolCall` 校验 → 返回 `AgentLoopDecision`（`tool/ask/done/say/stopped/paused` 六选一）。自身**不带循环**。
- 桌面 `runToolLoop()`（`agent.ts`）：`for(;;)` 中 `hooks.next(loopId, result)` 要决策 → `toolToAction` 映射 → `drive(action, wcId)` 执行（20 秒超时）→ 回执喂回下一次 `next`，直到 done/ask/say/stopped/paused。
- 决策只依据**最新页面快照**（`PageSnapshot` 文本摘要，非截图/视觉），历史通过 `assistant.tool_calls + tool` 消息连续保存在服务端内存。

首格强制工具调用已加上（`askModel` 中 `toolChoice: isFirstStep ? 'required' : 'auto'`，这是针对 BUG_LIST P1-1 的修复）。

## 三、工具调用（Tool/Function Calling）现状

### 1. 工具清单

**（A）浏览器驾驶工具（`toolLoop.ts` 的 `LOOP_TOOLS`，共 6 个，OpenAI 兼容 function 定义）：**

| 工具名 | 功能 |
|---|---|
| `open_url` | 在工作台浏览器打开 http(s) 网址（需换站/当前页非目标站时用） |
| `read_page` | 读当前页 url/title/可见按钮/链接/输入框/正文片段/字段分类 |
| `click` | 按 target 文本点击可见元素 |
| `type` | 往输入框输文字（`submit=true` 回车提交）；搜索类目标必须真打进搜索框 |
| `scroll` | 上/下滚一屏 |
| `stop` | 结束循环：`reason=done`（给结论）/`need_user`（卡住问用户）/`blocked`（页上做不了，给替代路） |

**（B）聊天路径工具（`search/chatTool.ts`，仅 1 个）：**

| 工具名 | 功能 |
|---|---|
| `web_search` | Tavily 联网搜索公开资料（标题/网址/摘要），纯 HTTPS，不开浏览器，一轮最多 3 次 |

**（C）本地执行动作（`shared` 的 `BrowserAction`，`driver.ts` 的 `drive()` 入口，共 12 种）：**

`open_url / click / type / scroll / wait / read_page / screenshot / ask_user / done / fill_form / focus_sensitive_field`（`ask_user/done` 在 driver 层仅"类型占位"，返回未实现；`screenshot` 只 driver 层可用，不在 LOOP_TOOLS 内，模型调不到）。

注意 P2-7 指出的问题仍然存在：`LOOP_TOOLS`（6 个）与 `BrowserActionType`（12 种）是**两份手工维护的清单**，无派生/断言保证一致。

### 2. 工具如何注册和管理？

**无统一 Tool Registry / Tool Schema 中心。** 现状是三处各管一段：

1. 服务端 `LOOP_TOOLS`（`as const` 数组）→ 随 `llmFetch` 的 `tools` 参数发给模型；
2. 服务端 `sanitizeToolCall()`（`toolLoop.ts`）→ 模型返回的 tool_call 先过"存在性 + 参数 JSON + URL/支付/敏感"三道闸，脏动作转人话提问；
3. 桌面 `drive()` 入口的 `validateBrowserAction()`（`driver.ts`）→ IPC 形状校验（只查形状不查语义），以及执行时的 `typeSensitiveGuard` / `payClickGuard` 第二道闸。

### 4. LLM 如何决定调用哪个工具？调用协议？

- **模型侧**：标准 **OpenAI 兼容 function calling**。`llmFetch(env, messages, { tools: LOOP_TOOLS, toolChoice })` POST 到 `{DEEPSEEK_BASE_URL}/chat/completions`，模型回 `choices[0].message.tool_calls`，服务端只取**第一个**记入历史（其余忽略，保证 assistant.tool_calls 与 tool 回执一一对应）。**不是 MCP 协议**，无 MCP server/client。

## 四、浏览器操作现状（重点）

### 1. 如何实现？是否封装成独立工具？

- **实现**：Electron 主窗口渲染层的 `<webview partition="persist:workbench-browser-project-<projectId>">` 承载真实网页；主进程 `driver.ts` 用 `webContents.debugger`（CDP 1.3）驱动该 webview 的 guest `webContents`。**无 Playwright/Puppeteer/Selenium/无头浏览器/外部 Chrome**。
- **封装形态**：执行原语收敛在 `driver.ts` 的**唯一入口 `drive(action, targetWebContentsId)`**；渲染层经 IPC `workbench:drive` 调用，主进程驾驶循环经 `exec` 钩子调用。页面侧能力（查找/快照）是注入的 `PAGE_HELPERS` JS（v12）。可以认为"已封装成独立执行器"，但**不是独立进程/服务**，与 Electron 主进程同进程。

### 2. 浏览器相关核心代码

**目标解析（fail-fast，不盲选，`driver.ts`）：**


**CDP attach + 8 秒统一超时闸（`driver.ts`）：**

```ts
const CDP_TIMEOUT_MS = 8000;
function ensureAttached(wc: Target): Electron.Debugger {
  const dbg = wc.debugger;
  if (!dbg.isAttached()) dbg.attach('1.3');
  if (!cdpPatched.has(dbg)) {  // 给 sendCommand 打超时补丁，新动作自动受保护
    cdpPatched.add(dbg);
    const raw = dbg.sendCommand.bind(dbg);
    dbg.sendCommand = ((method: string, commandParams?: unknown, sessionId?: string) =>
      Promise.race([ raw(method, commandParams as never, sessionId),
        new Promise((_resolve, reject) => { setTimeout(
          () => reject(new Error(`页面 ${CDP_TIMEOUT_MS/1000} 秒没有响应这条指令（${method}）`)), CDP_TIMEOUT_MS);}),
      ])) as typeof dbg.sendCommand;
  }
  return dbg;
}
async function evaluate<T>(wc: Target, expression: string): Promise<T> {
  const dbg = ensureAttached(wc);

    { expression, awaitPromise: true, returnByValue: true, userGesture: true })) as CdpEvalResponse;
  if (res.exceptionDetails) throw new Error(…);
```

**点击（`clickTarget`）：先 `scrollIntoView` + 命中测试（`elementFromPoint`，跨 frame 分层测），命中走 CDP 真实鼠标（mouseMoved→mousePressed→mouseReleased），不命中退化 `el.click()`；点前后比 `pageKey()`（url|title|节点数）得 `noChange`；App 唤起协议（`bytedance://` 等）直接拒并给下一步。**

**输入（`typeInto`）：聚焦+清空+真实鼠标预点击，四层写入兜底（`Input.insertText` → 逐字符 `dispatchKeyEvent`(≤30字) → `execCommand('insertText')` → 原生 setter+InputEvent），每次写后读回 `el.value` 校验；`submit` 三层回车兜底（CDP 回车 → 合成 KeyboardEvent → `form.requestSubmit()`）。**

**滚动（`scrollPage`）：真滚轮（2 秒超时）→ JS 兜底（window + 视口中心可滚动容器都滚）→ 两路不动则抛错明说。**

### 3. 浏览器会话如何管理？

- **多标签页**：渲染层 `useBrowserWorkspace.ts` 维护 tabs（每 tab 一个 `<webview>`，`BrowserPanel.tsx` 渲染）。上限 `maxBrowserInstances`（默认 4，可调 1~20），**只拒绝新开、绝不自动关页**。支持浅休眠（`setBackgroundThrottling`，省 CPU 不卸载）与深休眠（渲染层卸载 webview，省内存）。
- **会话隔离粒度 = 项目**：`partition="persist:workbench-browser-project-<projectId>"`，同项目多智能体共享 cookie/localStorage，跨项目隔离。标签页/任务仍按 `agentId` 隔离（渲染层 + 服务端硬闸）。
- **非单例**：每页独立 guest + 独立 Lane + 独立服务端 LoopSession + 独立页级状态分片（`pageState.ts` 按 wcId）。
- **下载**：按项目目录落盘（`<userData>/browser-projects/<projectId>/downloads`），每条记录带 `agentId`（`_downloads.jsonl`）。

### 4. 目前支持哪些浏览器操作？

| 操作 | 说明 |
|---|---|
| `open_url` | 跳转 + 等 `did-stop-loading`（30s 超时）+ 500ms 渲染等待 |
| `click` | 真实鼠标优先 + `el.click()` 退化 + noChange 检测 |
| `type` | 四层写入 + 读回校验 + 可选 submit |
| `scroll` | 真滚轮 + 双容器 JS 兜底 |
| `wait` | 等待 n 秒（上限 30s；形状校验允许到 300s，执行时夹到 30s） |
| `read_page` | 快照（url/title/按钮≤40/链接≤40/输入框≤40/正文≤60/loginLike/overlay/challengeLike/字段分类） |

| 新开 tab | 内嵌页 `window.open/target=_blank` → 主进程推 `opentab` 事件 → 渲染层 `openUrl()` 真开一条 tab（同智能体归属） |

### 5. 元素定位策略

**纯 DOM 策略，无坐标点击（不含 AI 视觉识别，截图不进模型）**。页面侧 `PAGE_HELPERS v12` 的 `find(target)` 五级降级：

1. 当 CSS 选择器试（支持逗号列表），遍历**所有匹配取第一个可见**（`queryDeep` 穿透 open shadow root + 同源 iframe，`MAX_NODES=20000`，`MAX_DEPTH=6`）；
2. placeholder / aria-label / name / id / title 精确命中；
3. 可见文字精确命中；
4. 可见文字包含；
5. 兜底：任意可见叶子节点文字包含。

`type` 专用 `findInput`：文字对不上时按"搜索语义 > 在视口内 > 面积大"打分挑真实 input/textarea；同轮按 target 缓存命中元素（防读回校验误判）。`click` 专用 `findClickable`：仅当 target 明显说"框/输入"时才退回输入框。

### 6. 异常处理机制

| 层级 | 机制 |
|---|---|
| IPC 形状 | `validateBrowserAction`：非法动作直接 `ok:false` + 人话，不抛栈 |
| CDP | 每命令 8 秒超时（`ensureAttached` 补丁）；滚轮命令额外 2 秒超时 |
| 执行 | `runToolLoop` 每步 20 秒 `Promise.race` 超时（超时当失败喂回模型） |
| 导航 | `loadURL` 等 `did-stop-loading`，主 frame `did-fail-load`（除 -3）判失败，30s 封顶 |
| 失败解释 | `failureHint(snap)`：按 `loginLike/overlay` 给"可能原因 + 一个明确下一步"，不退回整段重确认 |
| 本地安全网 | 同动作连败 2 次转 ask（`FAILS_BEFORE_ASK`）；连点 3 次无变化转 ask（`STALE_BEFORE_ASK`，但 P2-2 指出 `read_page` 会清零计数，实际难触发）；`type` 找不到框且目标是搜索 → 直接开百度搜索结果页兜底（P0-3 指出该兜底可能绕过敏感申报） |
| 暂停恢复 | 暂停门（`pausedOf(wcId)` 拦 `click/type/fill_form`）+ 服务端挂起（`paused` 态不调模型）+ 继续时重读页算 delta（unchanged/moved/edited/unknown）+ 步数归零 |

### 7. 安全限制

| 限制 | 位置与口径 |
|---|---|
| 敏感字段双闸 | 页面侧 `sensitiveish`（连 `value` 都不读）→ Node 侧 `fieldClass.classifyField` 唯一判定（password/otp/payment/id）→ 服务端 `sanitizeToolCall` 先挡 + 本地 `typeSensitiveGuard` 再挡；`fill_form` 逐字段拒；第 28 步 `risk:'sensitive'` 标记使循环**确定性停下申报**（不依赖模型自觉） |
| 支付守卫 | `payClickGuard` + `isPaymentConfirmAction`：收银最终确认 AI 不代点，`risk:'pay'` 必须用户自己点 |
| 分区闸 | 主进程 `will-attach-webview` 同步改写非法/跨账号分区到隔离分区 `…-none`（`decideWebviewPartition` 纯函数可测）；只认当前账号项目列表（渲染层 `syncProjects` 显式同步） |
| 协议拦截 | webview `setWindowOpenHandler` + `will-navigate/will-redirect/will-frame-navigate` 拦截非 http(s)（不弹系统框、不冲掉当前页）；主窗口 `will-navigate` 禁止跳外部站；外链只 `shell.openExternal` http(s) |
| 凭证隔离 | JWT 只存主进程内存；`agentApiBase` 只放行回环地址（`isLoopbackBase`）；渲染层无 Node（`contextIsolation/nodeIntegration=false/sandbox`），能力仅白名单 `window.workbench` |
| 下载脱敏 | 结果文档下载前替换 Bearer/sk-/手机号；任务文档 prompt 禁止出现凭证 |
| 聊天侧 | 本地正则拦"密码/验证码：xxx"类赋值发送；记忆/知识库写入前后过敏感闸 |

诚实边界（代码注释自述）：分区闸**拦不住同一账号多项目之间**（渲染层合法共存多项目页）；暂停有"每格才检查"的竞态窗口（P1-6，暂停后可能多执行 1 个动作）。

```
       → 同 loopId 原地接上；loop_gone(循环已回收) → 必须用户点"重新开始"才建新轮（P0 止血）
```

### 1. 能跑通的完整场景举例

基于代码路径（非真机验证）可确认跑通的场景：

1. **纯开页**："打开百度" → 本地 `detectOpenUrl` 命中 → 中栏真开一页 + 聊天一句"已打开"（后端/模型没起也能开页）。
2. **页上任务**：有活页时说"在这个页面搜一下 AI" → `prepareDrive` → 服务端建循环 → 桌面 `runToolLoop` 拉取 → 模型选 `type(搜索框)+submit` → 页跳结果页 → `stop(done)` → 聊天收结论 + 任务文档 + 红点。
3. **闲聊/查资料**："你好"、"今天美元汇率？"（无活页或无页面指代）→ 聊天分支，模型自主决定调 `web_search`（Tavily）→ 流式回答 + 气泡下可点来源（落库，可活过刷新）。
4. **暂停/继续**：任务中点暂停 → 本地停手 + 服务端挂起（保留历史）→ 用户手点页面 → 点继续 → 重读页 + delta 判定 + 同循环原地接上（`docs/acceptance/pause-resume/` 有 12 场景截图）。
5. **敏感/支付**：遇到密码/验证码框或支付确认 → 双闸挡下 → `risk` 标记 → 确定性停下 + 求助卡/🔒提示 → 用户在真实页自操作 → 自动恢复观察（导航/标题变/敏感框消失，上限 10 分钟）或手动继续。
6. **多路并行**：两智能体各一张页同时跑任务，`wcId/agentId` 双闸防串（`docs/acceptance` 有多路验收）。
7. **登录/记忆/知识库**：XYZ 号 + 短信（mock 转码到登录页）/ 密码登录；引导表建智能体；`tidy` 总结两层记忆；知识库上传检索（关键词字面匹配，非向量）。
