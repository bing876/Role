# 待办：R4 残留 - 有活页 + 页面指代但动词不在词表 → 不发车

- 发现时间：2026-09-22 R4 真服务端复验（`docs/acceptance-r4发车收紧-真服务端复验-20260922.md`）
- 状态：**记录，本次不改**。R4 已被 `b1052da` 确认为健康基线，单方面放宽动作词表会回退第 5 项精度
  （第 5 项是整套断言里**唯一有鉴别力**的一项，见复验报告「反证」节）
- 位置：`apps/server/src/routes/chat.ts` `shouldEnterTaskMode` 的 `STRONG_ACTION` / `WEAK_ACTION` 两张词表
- 现象（实测，真服务端 SSE 取证）：
  - 「当前页面上的价格帮我记下来」（hasPage=true）→ 不发车，走普通聊天
  - 「在这个页面帮我留意一下有没有货」（hasPage=true）→ 不发车
  - 原因：「记」「留意」既不在 `STRONG_ACTION`（打开/访问/点击/填/下单/整理/分析/诊断…），
    也不在 `WEAK_ACTION`（搜/查/看）。有页面指代 `PAGE_REF` 命中也没用 —— 规则要求
    「弱动作词 **AND** 页面指代」，缺了动作词这一半
- 性质判定：**这是 R4 的有意取舍，不是实现走样**。复查报告给 R4 的口径就是
  「有活页时：只有强动作词，或 弱动作词+页面指代 才发车」，即「宁可漏发不误发」。
  这两句已被 `scripts/verify/r4-intent-source-parity.mjs` 的 D 段按现状固化，
  谁改了词表都会立刻报出来
- 影响：与 `ARCHITECTURE_REVIEW.md` 的 **P0-1 同类症状**（AI 嘴上答应、手上不动）。
  普通聊天分支的工具表只有 `web_search`，结构上开不了浏览器 ⇒ 用户让它在当前页记点东西，
  它会答应但做不到。范围比修复前小得多（修复前是「几乎所有聊天都发车」，现在是「一类明确的
  当前页指令不发车」），但用户视角的困惑是一样的
- 建议后续方案（待讨论，三种，代价各不同）：
  1. **扩 `WEAK_ACTION` 词表**（加 记/记下来/留意/对比/找/看看有没有…）
     —— 最省事，但是「只补正则永远追不上用户措辞」（`ARCHITECTURE_REVIEW.md` 结论 §修复优先级 1 原话），
     且每加一个词都要重跑第 5 项确认没把闲聊放进来
  2. **有活页 + `PAGE_REF` 命中 → 直接发车**（不再要求动作词）
     —— 覆盖最全，但「你觉得这个方案怎么样」（在当前页聊）这类会误发；需要同时补一批
     「有页面指代但仍应走聊天」的反向保护用例
  3. **按 `ARCHITECTURE_REVIEW.md` 的原方案：发车判定改「服务端能力协商 / 模型裁决兜底」**
     —— 唯一能让 P0-1 全体症状消失的改法，但工作量大，且引入一次额外模型调用（与 R9「无 LLM 费用熔断」
     联动，得先有配额闸才敢上）
- 验收要求（改完必须跑的）：
  - `node scripts/verify/r4-intent-source-parity.mjs` —— D 段那两条要按新行为改期望值，A/B/C 段不许退化
  - `node scripts/verify/r4-dispatch-acceptance.mjs` —— 第 5 项 5/5 + 第 6 项 5/5 + `liveLoops` 计数一致
  - 反证：`REPO_DIR=<旧代码 worktree> EXPECT=fail5` 仍必须失败（证明断言没被改成无鉴别力）
