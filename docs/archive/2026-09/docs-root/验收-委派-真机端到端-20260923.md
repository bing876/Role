## 3. 使用说明（怎么自己用起来）

### 3.1 前提：项目里必须有 ≥2 个智能体

开箱只有「小助」一个 ⇒ 名单里写着「目前没有别的智能体，`delegate` 现在没人可交，别调用它」。

建智能体：左栏 **「＋ 添加」** → 新会话里出现**引导表**（名称 / 它是谁 / 怎么说话 / 干什么）→ 点确认。
★ **不填引导表，名字就是「新智能体」**，建几个都同名，模型没法指名委派。

### 3.2 触发：模型决定，用户只用自然语言

不需要任何按钮。说一句带**强动作词**且提到同事的话，例如：

> 「整理一下国内三家主流云厂商的对象存储定价，这件事更适合**资料员**来做，交给它去查，我要三个要点。」

★ 前提是**当前有绑定的内嵌页**（`App.tsx:2198` 要求 `effectiveWcId` 是数字）——
没开页时服务端循环会建起来，但桌面端**永远不会去驱动它**（现象：界面停在「AI 任务执行中」、
`/health` 的 `llmCalls` 一直不动）。先开一张页再发指令即可。

### 3.3 看结果：🗂 内部频道

顶栏「🗂 内部频道」→ 左侧选频道 → 右侧看 派活/过程/交活 时间线。**只读**（只有刷新/关闭）。

## 5. 驱动 UI 时踩到的三个坑（供后续写自动化脚本参考）

1. **发消息**：`setter + 派发 input 事件 + 点发送按钮` 会被 React 重渲染吃掉 ⇒
   改用 **点输入框聚焦 → CDP `Input.insertText` 真实键入 → 回车**，并用「输入框是否被清空」自检。
2. **开页后界面会切到浏览器视图**，聊天输入框**不在 DOM 里** ⇒ 要再点一次「切回对话」。
3. **★★★ 按文字点按钮不能取「最后一个」匹配元素**：AI 的回复正文里含「过程可以在**内部频道**里看」，
   取最后一个就点到了**聊天气泡**上 ⇒ 顶栏 tab 连点 4 次都打不开。
   改成**取文本最短**的匹配元素即可。
