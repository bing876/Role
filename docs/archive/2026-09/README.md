**为什么还有一些资料留在 `docs/acceptance/`？**现行上线清单、2026-09-30 仍用于安全拍板的三份记录、自动检查直接读取的 `ci-fast-feedback.golden.json`、原始图片和数据都不能当“旧文字报告”搬走。三份依赖原位截图或记录的操作指南也暂原位；如要再次整理，先看 [`../../拟删清单-待拍板.md`](../../拟删清单-待拍板.md) 并询问用户。原位保存不等于这些证据证明了最新版本的真 GUI。依据：`docs/acceptance/完模式-交付汇总与上线真机清单.md`、`scripts/verify/p2-idle-scan-bounded.mts`。

**找文件的方法：**打开迁移映射，搜索旧路径，可看到新路径与内容校验值。旧报告及产品代码注释里的旧路径可能没有同步改写——为了遵守“不碰代码”，不要据此删除证据或推断功能坏了。归档报告中旧相对截图链接可能不再直接可点；到映射对应的原 `docs/acceptance/` 子目录找仍原位保留的图片或数据。7 组同名字节相同，Git 的重命名识别可能把它们对调显示；映射以**原目录 + 文件名 + SHA-256** 为准，8 份原有 archive 均放在 `legacy/`。当前活文档索引：[`../../README.md`](../../README.md)。
