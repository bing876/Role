- **日期**：2026-09-20
- **对应你第四次报障**：「@截图 你到底在修复什么啊为什么会这样？到底需要怎么做才能进入工作台」
- **一句话**：后端其实**一直在自愈**（40 秒内就好了），但登录页在那期间甩了一句红字、
  **而且不会自己重试**；再加上应用自己拉起的服务端**用户看不到任何窗口**，
  验证码根本拿不到。这两件事现在都修了。

## 一、你截图那一刻，现场到底是什么状态

我把当时的现场量了一遍（就在你截图后 1 分钟）：

| 项 | 实测 |
| --- | --- |
| `/health` | `{"service":"ai-workbench-server","db":"down"}` → **4 秒后变成 `"up"`** |
| `POST /auth/sms/send` | **200** |
| `POST /auth/login/sms` | **200 + token，user.id=67 / XYZ69376** |
| 进程 | PG PID 13280、服务端 PID 16288、应用 PID 29064 —— **三个都在跑，连接是通的** |

**所以后端没坏。** 你看到的是**启动那 40 秒里留下的旧报错**，页面不会自己重试，
也不会在好后把红字撤掉。这就是"明明修好了却还是进不去"的真相 ——
**不是功能没修好，是界面在骗人。**

## 二、根因（两条，都是我上一轮留下的）

1. **报错报早了、且不撤销。** 登录页一发现 `fetch` 失败就写死
   「连不上后端 … 先双击 start-dev.cmd … 再重试」，而应用此刻正在后台自己拉库、拉服务端
   （冷启动最坏 ~40 秒）。它**不会重试**，也**不会在好后把那句话撤掉**。
2. **验证码拿不到。** 应用自己拉起服务端时，服务端的 stdout 走 `stdio: 'pipe'` 被主进程接管 ——
   那行 `[sms:mock] → 186****4444 验证码 169532` 只进了管道，**用户看不到任何窗口**。
   `start-dev.cmd` 那个「AI工作台-服务端」窗口根本不存在。
   → 也就是说：**能连上后端，却拿不到码**，"打开应用就能登录"实际上不成立。

## 三、改了什么

| 文件 | 改了什么 |
| --- | --- |
| `apps/desktop/src/App.tsx` | ① 每 2 秒自己重探 `/health`（认 `service` 标识，与主进程同口径），探测期间只显示「正在准备后端…（已等 N 秒）」；探到就**自动把红字撤掉**。② 请求失败若是"连不上后端"，改成**重新排队等后端**而不是报错。③ 显示「本次验证码：XXXXXX」 |
| `apps/desktop/electron/main.ts` | 新增 `relayServerLog`：把服务端日志里 `[sms:mock]` 那行解析出来，`sendToMainWindow('workbench:sms:mock')` 转给登录页 |
| `apps/desktop/electron/preload.ts` | 暴露 `onSmsMockCode`（与主进程同名通道，否则发了没人收、静默失效） |
| `packages/shared/src/index.ts` | `WorkbenchBridge` 加 `onSmsMockCode` 类型 |
| `.workbuddy-ai/swap-dist.mjs` | STAMP → `login-autoretry-r7`；canary → `正在准备后端`；新增 7 条本轮自检 |

**设计边界（刻意保留）**：验证码转发**只在服务端是应用自己拉起时生效**。
如果服务端是你手动起的（`start-dev.cmd`），那它有一个可见的控制台窗口，
码就在窗口里 —— 两种情形都拿得到码，不会出现"都拿不到"。

## 六、本轮踩到的三个坑（都写进记忆了）

1. **Edit 工具报"成功"但文件没变** —— 本轮**复发三次**（`server-supervisor.ts` 两处、`swap-dist.mjs` 的 STAMP）。
   后果：上一轮（r6）我以为把 STAMP 改成了 `pg-supervisor-r6`，**实际还是 `db-hint-r5`** ——
   所以 r6 那次换装的备份名/归档名全部撞车（这才是"备份名复用"的真正原因，
   我上一份报告里写的"同名不覆盖"只是表象）。
   → **改完关键常量必须 `grep` 复查**，不能信 Edit 的返回。
2. **本机有个外部进程会反复重建构建产物** —— 实测 01:34 换装、**01:35:19 `dist-electron/main.js` 又被写了一次**。
   于是"拿包里的文件与**当前**构建逐字节比"必然对不上 —— 那是**用例错**。
   构建产物是个会动的靶子，不能当基准。
   → 核对口径改成"**装进去的那份里有没有本轮的新代码**"，逐字节比对降级为参考信息。
3. **反证/探针的前提没造干净 → 假红** —— 探针第一版直接启动应用，但 8787 上还留着上次探针的服务端，
   于是应用走「已有服务端在跑，直接用（不接管）」、**主进程收不到 `[sms:mock]`**，验证码自然转发不出来。
   不是 bug，是**前提没造对**。同理还有两处：连上 CDP 就读 `innerText`（首帧还没画，拿到空串）、
   没填手机号就断言"按钮该可点"（`disabled` 里本来就有 `phone.length !== 11`）。
   → **测试变红先分辨"代码错了"还是"用例错了"**，本轮三次都是用例错。
