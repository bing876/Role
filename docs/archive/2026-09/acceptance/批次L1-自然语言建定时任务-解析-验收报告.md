## 1. 实现:`apps/server/src/orchestrator/routineParser.ts`

`parseRoutineIntent(message: string): RoutineIntent | null`

### 1.1 接受的两类句式(有意收窄,宁漏勿误建)

| 族 | 句式 | 例子 |
|---|---|---|
| **F1 祈使族** | 让/请/叫/安排 + [智能体名] + 节奏 + 任务 | 「让运营助手每天9点检查店铺数据」「请客服每天早上八点处理退款咨询」「让数据员每天下午3点30汇总本周报表」「让夜值凌晨两点巡检服务器日志」「让运营每30分钟刷新一次店铺页面」 |
| **F2 节奏起头族** | 每天/每日 + [时刻] + 提醒我/帮我/替我/给我 + 任务 | 「每天9点提醒我喝水」「每天晚上10点半提醒我复盘今天」 |

节奏锚的位置由**锚点搜索**决定(不是写死的"动词+名字+节奏"一条正则):名字段可以空(「让每天9点检查…」),节奏可以是"每天+时刻"、"每N分钟/小时"、或**裸时刻**(「让夜值凌晨两点巡检…」→ 每天 02:00)。

### 1.2 时刻口径(与 `computeNextRun` 对齐)

- 数字/中文数字:「9点」「八点」「下午3点30」「晚上10点半」「9点45分」「09:30」;
- 时段偏移:下午/晚上/夜里 <12 点 +12;半夜/深夜 12点=0 点;
- **只说时段**(「每天早上提醒我交周报」)→ 按时段默认(早上 09:00、晚上 21:00、中午 12:00…),`timeDefaulted=true`;
- **完全没说时刻** → 默认每天 09:00,`description` 里**如实**写"(没说话里没给时刻,默认每天 09:00)"。
- 间隔:每 N 分钟/每 N 小时/每半小时/每小时,范围 **5 分钟 ~ 7 天**(与 `computeNextRun` 的 clamp 一致);「每分钟检查一次」(<5 分钟)直接 null——照建就是骗人。

### 1.3 守卫(宁漏勿误建,每条都有验收钉住)

1. **问句词**(怎么/如何/为什么/是什么/哪些/能不能/**吗**…):「怎么设定期任务?」「让运营助手每天9点检查数据可以吗?」→ null。
2. **建智能体的话归批次 E**(建/创建/来个 + 助手/智能体/同事/机器人/专员/管家):「建一个销售助手」「请建一个每天9点检查数据的助手」→ null,不抢。
3. **一次性时间词**(明天/后天/今晚/今夜/稍后…):「让X明天9点检查数据」→ null(单次,不是定期)。
4. **名字段校验**:锚前面的片段当"名字"时,必须是 1~8 字中文/字母;虚词(「一个」)、功能字(「把/就/的/给」)、任务动词(除非"XX员/手/师"岗位名,「检查员」放行、「助手检查」拒)→ 拒。
5. **裸时刻后紧跟"前"** = 截止时间不是日程:「让X9点前交报告」→ null。
6. **任务以"的"开头** = 前面是名词短语不是任务:「让每天9点的例会改到10点」→ null。
7. **F2 必须紧跟"对我做点什么"前缀**(提醒我/帮我/替我/给我):「每天早上喝咖啡」「我每天早上都喝咖啡」「我们每天9点例会」→ null(反证②钉的就是这条防线)。

### 1.4 name/description 自动生成(身份/名字生成)

- `name` = `<节奏标签>·<任务>`(如「每天 09:00·检查店铺数据」,≤80);
- `description` = `自然语言创建:<原句>`(≤300;时刻是默认出来的会追加说明)。

## 3. 反证(拆一个机制,验收必须红)

`npm run verify:routine-parser:revert`,~25s:

| 变异 | 拆法 | 咬住的位置 |
|---|---|---|
| L1a 祈使动词拆掉 | `DIRECTIVE = '(?:让|请|叫|安排)'` → `'(?:永|无|此|句)'` | 红在「让运营助手每天9点检查店铺数据」(F1 族整族失效) |
| L1b F2 前缀放宽成任意字 | `F2_PREFIX = '(?:提醒我\|帮我\|替我\|给我)'` → `'(?:.{0,3})'` | 红**恰好**在「每天早上喝咖啡」(闲聊被误建) |
| L1c 问句守卫停用 | `QUESTION_RE` → 永不命中 | 红**恰好**在「让运营助手每天9点检查数据可以吗?」 |

★ 两处自我纠偏(和收尾 9 的 K3 同一课:**红的必须是机制本身,不是副作用**):
1. **L1b 第一版**用的是**捕获组** `(.{0,3})`——组号把后面任务组顶掉,验收也红了,但红在"任务变成前缀"的组号错位上,而"每天早上喝咖啡"那条**居然没误建**(被组号错位碰巧救回)。改成**非捕获** `(?:.{0,3})` 后,红的才真正落在"闲聊被误建"本身上。
2. **L1c 第一版**用的句子是「怎么让运营助手每天9点检查数据」——注入后**不红**(exit=0):句首的"怎么"本来就被 F1 的句首锚挡掉,拆不拆守卫都一样。问题词必须落在祈使锚**之后**(「让…可以吗?」),守卫才是唯一防线。为此给 `QUESTION_RE` 补了「吗」。

三次注入源码均逐字节还原(md5 比对),还原后复跑 exit=0,最终反证失败项 0。

## 4. 已知边界(如实说)

1. **只支持两种词序**:「让X+节奏+任务」和「每天…提醒我+任务」。节奏在句尾的(「让X检查店铺数据,每天9点」)→ null 回落 LLM。
2. **裸时刻按"每天"算**(「让夜值凌晨两点巡检…」= 每天 02:00)。单次的由 明天/今晚 守卫挡;没被挡住的裸时刻句子(如「让X两点巡检」)会被建成每天——这是有意取舍(宁可偏建,LLM 兜底前给用户明确结果)。
3. **英文/混排名字**只认字母(「让GPT助手每天…」行);全英文句子不解析 → LLM。
4. 解析器**不知道名册**:`agentName` 是原话,解析成 agent_id 是 L2 的事(查不到名字时 L2 的回话口径另行设计)。
5. 确定性:纯函数,无 IO、无 `new Date()` 进结果,同句两次解析逐字段一致(已断言)。
