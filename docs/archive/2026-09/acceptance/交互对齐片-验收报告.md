## 五、自动化测不出的主观项(请亲自看一眼)

1. **状态行的位置与分量**:它现在是「聊天流里的一行小字 + 旋转」。你希望它更显眼一点(比如钉在输入框上方),还是就这样?
2. **轨迹抽屉的入口文案**「执行轨迹 · N 步(点开看)」—— 点开的冲动够不够?要不要把最近一条也显示在摘要里?
3. **「停止」按钮的红色**:现在是白底红字。会不会太"重"?或者正好?
4. **markdown 的字号/行距**:我在助手气泡里给列表/代码块定了很朴素的样式(没有设计稿)。看着舒不舒服?
5. **补一句话时的反馈**:现在完全静默(只有气泡上屏)。要不要在状态行里加一句「已收到补充要求」?

## 六、剩余风险与已知缺口

1. **「停」之后界面仍显示执行中**:`/agent/loop/pause` 是**挂起**(可「继续」),服务端不会结束那条 SSE ⇒ 桌面 `runningLoopId` 还在 ⇒ 状态行 + 「停止」键仍在。**是否要把「挂起」也画成非执行态**需要你拍板(见终报③)。
2. **`verify:loop:kill9` 仍是红的**(既有,与本片无关)。
3. **下载同名会静默覆盖**(`item.setSavePath(原名)`),上一片就登记过,未修。
4. **客户端站点表**:`detectOpenUrl` 认不出站名就开不了页(用户已抱怨过一次);本片只做了「开页优先」,没动站点表。
5. **长任务真机重启续上**未验证;`verify:loop:kill9` 的既有失败意味着这条链当前**不可信**,要修它才能真验。
