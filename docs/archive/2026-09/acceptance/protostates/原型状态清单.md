## 怎么看这份清单

原型的 `.frame` 出厂时只有一个 `class="frame"`，**所有状态类都是运行时由 JS 加上去的**。
所以"有多少种状态"不是数 HTML 里的静态 class，而是数 JS 能把它切成几种样子。
下面按"顶层 frame 状态"和"局部组件状态"分开列——顶层状态会改变整屏骨架，组件状态只改局部。

截图手法：每个状态前**整页 reload** 再触发，避免上一个状态的残留污染下一张
（第一版吃过亏：只重置 `.frame.className`，结果 `.sidebar` 上留下的 inline `width:0`
没清掉，S05–S11 五张图字节数完全一样）。渲染前还会把 `.stage` 的 `scale(0.96)` 去掉，
拿到真正的 1:1 设计稿像素。

### ★ 重要发现：原型主区里根本没有消息列表

读 `.main-area`（HTML 第 2896 行起）可以确认，它内部只有两块 DOM：

```
<div class="main-area">
  <div class="top-area"></div>   ← 30px 高，注释写明「顶部预留插件区，当前不覆盖任何内容」
  <div class="inputbar">…</div>  ← 底部输入胶囊
</div>
```

没有消息容器、没有空态文案。所以 **S11 空态和 S01 默认是同一张图**（两张都是 46,568 B，哈希一致）。

原型里聊天内容实际出现在两处：
- `.sess-float` 会话浮窗（双击智能体拖出来）
- `.dual-view` 双栏对照（见 S18）

这意味着"列2 显示消息"**不是原型的设计**，是桌面端自己的东西。
先前你裁决过「列2：保留桌面端的消息显示」，所以消息列表保留；
但**空态文案已经按原型删掉了**（原本有一句"还没有和「X」聊过…"）。
