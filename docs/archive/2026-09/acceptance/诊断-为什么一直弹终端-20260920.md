# 诊断报告：为什么一直弹终端 + 工作台为什么一连串出问题

- **时间**：2026-09-20 02:17 ~ 02:21
- **范围**：**只排查，未改任何代码**
- **一句话**：有一个**早前那轮「暂停/继续」的验收测试**被 agent 当后台任务启动着，
  它在**反复杀掉并重启 PostgreSQL**，而重启用的是 `start "" postgres.exe` ——
  Windows 的 `start` **每起一次就新开一个可见控制台窗口**。工作台的一连串毛病也是它造成的。

---

## 一、黑窗口是什么

你截图里那个黑窗口的内容是 **PostgreSQL 自己的日志**：

```
2026-09-20 02:16:37.112 [WARN] LOG:  checkpoint starting: end-of-recovery immediate wait
2026-09-20 02:16:37.238 CST [14008] LOG:  checkpoint complete: wrote 27 buffers (0.2%) ...
```

`end-of-recovery` = PG 上一次是**被硬杀**的，这次启动在做崩溃恢复。
**所以这个窗口是 `postgres.exe` 的控制台。**

## 二、它为什么"一直"弹

因为 **PG 被反复杀掉又拉起**，而拉起的方式**必然弹窗**：

```bat
:: C:\Users\bing\workbuddy-ai\pg2\_boot.cmd（02:16 刚被重写）
@echo off
chcp 936 >nul
start "" "C:\Users\bing\workbuddy-ai\pg2\pg\bin\postgres.exe" -D "C:\Users\bing\workbuddy-ai\pg2\data"
```

`start ""` 是**新开一个窗口**运行 —— 每重启一次 PG，就弹一个黑窗。

## 三、谁在反复杀/起 PG —— 抓到了

进程树（`Get-CimInstance Win32_Process` 实测）：

```
bash.exe(12924)   ← codebuddy-shell-payload（agent 的 Bash 工具包装器）
  └─ python.exe(7404)  run-pause-resume.py
       └─ python.exe(28848) run-pause-resume.py
            └─ python.exe(2748)  pause-resume-tests.py
                 └─ python.exe(30920) pause-resume-tests.py
```

**是早前那轮「暂停/继续」的验收测试套件**，被某个 agent 会话以**后台任务**方式启动，
一直在跑（它自己那条命令是 `python -u scripts/verify/run-pause-resume.py`）。

`run-pause-resume.py` 干的事（源码第 57–95 行）：

```python
def ensure_pg():
    """先把**所有** postgres 杀掉，确保后面只跑一个实例。"""
    subprocess.run(["taskkill", "/F", "/IM", "postgres.exe"], ...)   # ← 无差别杀光
    time.sleep(3)
    ...
    'start "" "%s" -D "%s"' % (postgres.exe, data_dir)               # ← 弹窗式启动
```

它还会跑 `pause-resume-tests.py`，那个脚本会**自己起 Electron 实例**
（`node_modules/electron/dist/electron.exe` + `scripts/start-electron.mjs`，
证据：`docs/acceptance/pause-resume/electron.log`、`electron-restart.log`、`server-8791-restart.log`）。

### 关键证据：那个 PG **不是工作台起的**

| 事实 | 说明 |
| --- | --- |
| `postgres.exe` PID 1892 的 **父进程 = 23168**（已退出的 cmd） | 工作台起的 PG，父进程应该是 `AI 工作台.exe` |
| PID 1892 还带一个 **`conhost.exe` 子进程** | 说明它是**带控制台**启动的 → 有窗口 |
| 启动时间 **02:17:53** | 正好在 `run-pause-resume.py`（02:17:37 启动）之后 |

## 四、工作台"一连串问题"的原因

同一台机器上，**工作台**和**这个测试套件**在抢同一批资源：

| 资源 | 工作台要的 | 测试套件干的 | 后果 |
| --- | --- | --- | --- |
| 5432 PG | 一直可用 | **`taskkill /F /IM postgres.exe` 无差别杀光** | 工作台 db 掉线、`/auth` 503 |
| 8787 服务端 | 它自己那份 | 起/重启自己的（`server-8791-restart.log`） | 端口被抢、工作台请求打到别人身上 |
| Electron / 5173 | 用户那份应用 | 反复起 dev 实例并重启 | 抢焦点、抢 vite 端口、界面行为错乱 |

→ 你看到的「时好时坏、莫名报错、弹终端」是**同一个根因**：**有个测试在工作台运行期间抢资源 + 杀库。**

## 五、现在的状态（02:21 实测）

| 项 | 状态 |

| `run-pause-resume.py` / `pause-resume-tests.py` | **已退出**（02:20:20 跑完，日志结尾「全部通过」） |
| **它起的 4 个 `electron.exe` 测试实例** | **仍然活着**（残留，需要清） |
| 5432 | 在听（PID 32548） |
| 8787 | 在听（PID 2112 = `AI 工作台.exe`，工作台自己的服务端） |

## 六、建议（按优先级）

1. **立刻清掉残留的 4 个 `electron.exe`** —— 它们是测试实例，不是你的工作台。
   ```bash
   taskkill /F /IM electron.exe
   ```
   （`AI 工作台.exe` 不受影响 —— 打包版用的是 `AI 工作台.exe`，不是 `electron.exe`。）
2. **以后别在"正在用工作台"的时候跑验收测试** —— 那套脚本会无差别杀 PG、抢 8787。
3. **代码层面（下一轮再改，需你确认）**：
   - `_boot.cmd` / `start-pg.cmd` / `watchdog.cmd` 里的 `start ""` 改成**不弹窗**的方式
     （`postgres.exe` 直接 spawn 且带 `CREATE_NO_WINDOW`，或 `start "" /B`）。
   - 给 PG 定"**单一所有者**"约定：工作台已经在管 PG 了，测试脚本不该再自己起一份 ——
     否则必然出现"两个 actor 互相杀/互相起"的循环（这正是本机的老毛病）。
   - 后台任务要能**自己收尾**：这次是"测试跑完了但它的 Electron 子进程没被收走"。
