# 收尾 8 · 交接文件与 board 落盘前的脱敏 —— 验收报告

> 用户 2026-09-25 拍板并入阶段 1 的收尾顺序：**① 收尾 8（本批）→ ② 收尾 9（真 kill -9）→ ③ 批次 K → ④ 批次 L 只后端**。
> 本报告记录：改了什么、为什么、怎么验、反证怎么咬。

---

## 1. 问题（为什么这一批非做不可）

`handoffs/<delegationId>.md` 与 `board.md` 是**明文文件**（不像 `tasks.goal_enc` / `messages.content_enc`
那样有密文列），而它们的内容**全部来自模型与用户**：委派目标、上下文、产出要求、审批边界、
子循环原样报上来的**进度与结论**、board 那一行摘要。

同一句话在别处早就有闸：

| 通道 | 闸 | 位置 |
|---|---|---|
| 频道正文 | `redactForStorage(...)` | `orchestrator/channels.ts:63`（`safeText`） |
| 派工任务文本 | `redactForStorage(...).slice(0,1000)` | `orchestrator/channels.ts:270` |
| 摘要与要点 | `redactForStorage(...)` | `orchestrator/workers.ts:315,319` |
| **交接文件 / board** | **（缺）** | `orchestrator/handoff.ts` ← **本批补上** |

漏的后果很直接：**判定（要不要拒绝）在上游，落盘是最后一道兜底** —— 上游漏了一个形态，
磁盘上就是原文，而且交接文件会被**模型自己读回去**（委派消息只传路径），等于原文又回流进了上下文。

## 2. 改了什么（三道闸，一处口径）

只在 `apps/server/src/orchestrator/handoff.ts` 里动手，加一个局部 helper：

```ts
const safe = (t: unknown): string => redactForStorage(String(t ?? ''));
```

| # | 落盘口 | 改法 |
|---|---|---|
| 1 | **委派文件正文**（`buildHandoffMarkdown`） | 五个自由文本字段全部过 `safe()`：`goal` / `input` / `outputRequire` / `approvalBoundary` / 双方名字；**结构化字段**（delegationId / jobId / 项目 id / 状态 / 时间 / 路径）原样保留 |
| 2 | **board.md 追加行**（`appendBoardWithLock`） | `entry` 先过 `safe()` 再进临界区（纯函数，不占落库锁），写文件用 `safeEntry` |
| 3 | **追加的进度 / 结论**（`updateHandoffStatus`） | `extra` 过 `safe()`；段落时间戳保留（它是要给人看"什么时候更新的"） |

**口径**（与 R2 / 收尾 6 完全一致，没有新立标准）：`redactForStorage` 抹的是**值形态**
（银行卡 12~19 位 / 身份证 18 位 / 密码 / 验证码 / CVV / ≥21 位连续纯数字串），
只留「有几个字符」；它是**兜底**而不是"清洗后照发" —— 要不要**拒绝**这次委派仍由上游
`detectSensitive` 决定（那是使用规则 1）。

## 3. 验收（`npm run verify:handoff`）

脚本：`scripts/verify/handoff-redact.mts`（**跑的是生产代码本身**，不是副本）

- import 的是 `apps/server/src/orchestrator/handoff.ts` 的真函数；
- 库是 **PGlite**（真 PostgreSQL 编译成 WASM）→ board 的 `board_locks` 行锁真跑，`project_id` 外键也真判；
- 交接目录用 `HANDOFF_ROOT` 指到**临时目录**（`mkdtemp`）→ 绝不往仓库 `data/` 里写。

**输出（逐字）**

```
=== 收尾 8 · 交接文件与 board 落盘前的脱敏 ===
（临时交接目录：/tmp/handoff-redact-XXXXXX）

--- ① 委派文件：目标 / 输入 / 产出要求 / 审批边界 / 双方名字 ---
  ✓ 五个字段里的敏感值都落成了掩码，原文一个字都不在文件里
  ✓ ★ 不许涂花：正常的人话 / 路径 / id / 时间戳原样留着

--- ② board.md：那一行摘要是用户原话的截断，同样不许带原文 ---
  ✓ board 追加行里的敏感值已脱敏，结构（时间 / #id / A→B / 路径）还在

--- ③ 追加的进度 / 结论：子循环原样报上来的那一串 ---
  ✓ 进度与结论里的敏感值都脱敏了，状态行本身照旧可读

--- ④ 口径一致：同一句话，频道正文与交接文件的脱敏结果必须一样 ---
  ✓ 对拍 redactForStorage：交接文件里的掩码与它逐字一致

--- ⑤ 目录与文件确实落在 HANDOFF_ROOT 下（别写进仓库） ---
  ✓ 交接目录就是临时目录，仓库 data/ 里没有多出东西

=== 结论 ===
  6 PASS / 0 FAIL
```

**覆盖的敏感形态**（每条都真写进目标/输入/产出要求/审批边界/名字里）：
`密码是 Zx9!secret` / `银行卡 6222 0212 3456 7890` / `身份证 110101199003071234` /
`验证码 8421` / `订单号 1234567890123456789012345`（25 位 → longdigits）。
**判据是"原文一个都不在磁盘上"**（`FORBIDDEN` 逐个 `includes` 检查），不是"看到掩码就算过"。

**反向的一条（防过度脱敏）**：正常人话、`- 去向: 卡布 (#98)`、`handoff://77/5.md`、
`2026-09-25T00:00:00.000Z` 必须原样留着 —— 交接文件是给**模型读**的，涂花了等于把它废掉。

## 4. 反证（`scripts/verify/handoff-redact-revert-proof.py`）

三个落盘口**分别**拆掉，每个都必须当场红、且命中对应断言：

```
--- H1 委派文件的内容不再脱敏（目标/输入/产出要求/审批边界/名字里带敏感值就原文落盘）
  注入后：退出码=1
    ✗ 五个字段里的敏感值都落成了掩码，原文一个字都不在文件里
    ✗ 进度与结论里的敏感值都脱敏了，状态行本身照旧可读
    ✗ 对拍 redactForStorage：交接文件里的掩码与它逐字一致
  ✓ 变红，且命中「磁盘上是原文」

--- H2 board.md 那一行不再脱敏（用户原话的摘要原文落盘）
  注入后：退出码=1
    ✗ board 追加行里的敏感值已脱敏，结构（时间 / #id / A→B / 路径）还在
  ✓ 变红，且命中「board.md 里是原文」

--- H3 追加的进度/结论不再脱敏（子循环报上来的原文落盘）
  注入后：退出码=1
    ✗ 进度与结论里的敏感值都脱敏了，状态行本身照旧可读
  ✓ 变红，且命中「追加内容里是原文」

=== 结论 ===
  注入 3 个缺陷，被验收抓到 3 个
  反证失败项：0
  还原后：退出码=0（应 0）
```

每次注入后都**逐字节还原**（md5 对比），最后再跑一遍验收确认还原干净。

## 6. 本批**没做**的事（如实记）

- **没有**给 board / handoff 加密（它们是明文文件；要不要加密是批次 K / 阶段 2 之外的另一个话题）。
- **没有**动 `detectSensitive` 的判定口径（那是使用规则 1 的"拒绝"，与这里的"落盘兜底"两层）。
- **没有**清理历史遗留的明文 handoff 文件（`data/handoffs/**`）—— 与批次 K"旧明文列暂不 drop"同一口径，
  等用户拍。
