## 2. 打包

```bash
npx electron-builder --win nsis --publish never -c.directories.output=release-ui15
```

产物：`apps/desktop/release-ui15/AI-Workbench-0.1.0-win-x64.exe`（80,801,915 bytes ≈ 77 MB）

### 为什么要换输出目录

默认输出目录 `release/` 里残着上一次失败打包留下的 `win-unpacked` / `win-unpacked.tmp`。
electron-builder 试图清空它们时被**沙箱批量删除守卫**拦下：

```
⨯ [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":79,"threshold":50,
   "targets":["...\release\win-unpacked.tmp"]}
```

该目录此后**已无法从沙箱内清除**（回收站 / 删除 / 改名 / rmtree 全部失败，
报错带 `[safe-delete] ... "Some operations were aborted"` —— 是守卫垫片自己持有句柄）。
因此改为输出到全新的 `release-ui15/`，一次成功，无需绕过任何安全机制。

> 残留需用户手工删除：`apps/desktop/release/win-unpacked` 与 `win-unpacked.tmp`

## 5. 验收说明（重要）

**已完成的确定性验证**：读安装包内 asar 里的 CSS，逐项确认全部 UI-1.5 数值已进入成品
（`--wt-icon-size:28px` 等 6 项），且两处安装目录的 asar 与构建产物 sha256 完全一致。

**未能在此环境完成的一步**：由 agent 直接启动打包版 GUI 做「打开即新版」的肉眼确认。
本机实况：打包版 Electron 必须带 `--no-sandbox`（否则秒退）；即使以独立进程组
（`DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`）启动，进程也会在十几秒后被回收，
且 CDP `/json/list` 返回 `502 upstream connect failed`（端口在 listen 但已无渲染进程）。
**请双击桌面「AI 工作台」快捷方式自行确认**——文件层面已 100% 是新版。
