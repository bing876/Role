## 4. ⚠️ 提取过程中发现的内部矛盾 / 未定义项（**需用户裁决，未自行设定**）

### C1. 列1 / 列2 之间到底有没有 1px 分隔线？（**真矛盾**）

原型里同时存在**互相冲突**的三处声明：

| # | 声明 | 位置 | 含义 |
| --- | --- | --- | --- |
| a | `.rail { border-right: 0 }`，注释「第一/二列之间不再画线，两列同色无缝」 | `block0` Round 182 | **无线** |
| b | `--col-rail-brd: rgba(255,255,255,0.04)` 令牌仍存在 | `block0` | 令牌未删，暗示可能有线 |
| c | `.sidebar { box-shadow: -1px 0 0 0 var(--col-sidebar-solid) !important }` | `block1` Round 194 | **有 1px「线」**，但画的是列2 自己底色（视觉上不是线，是补缝） |
| d | `.sidebar` base 里 `border-right: 1px solid var(--col-sb-brd)` | `block0` | **列2 右侧**有 1px 线 |

**需要决定**：
1. 列1↔列2 边界：按 (a) 无缝（仅靠 (c) 的补缝 box-shadow 保证不露玻璃底）？还是保留 (b) 的 `rgba(255,255,255,0.04)` 细线？
2. 列2↔列3 边界：保留 (d) 的 `1px solid rgba(255,255,255,0.05)`？还是也改成 Round 194 的补缝方案（`.main-area { box-shadow:-1px 0 0 0 var(--col-main) }` 已存在，与 (d) 叠加）？**两者同时生效**，实际渲染会是「补缝色 + 1px 描边」叠在一起。
3. 补缝 `box-shadow` 是**为 `transform:scale` 小数像素场景写的 workaround**（注释说明：桌面端 1488×988 + scale 1 时没有这条缝）。本项目用 flex 布局、无 scale，**是否需要移植这个 workaround**？

### C2. `.contact-body` 42px vs `.contact-avatar` 41px 等高推导失效

`.contact-body` 上方注释写：「两行 22 + 4 + 16 = 42 → 与头像 42 严格等高」。
但头像在 `Round 192b` 已改为 **41px**，注释未同步更新。
- 行高 22 + 4 + 16 = 42 与头像 41 相差 1px。
- **需要决定**：以 **41px（头像实测值）** 为准并接受 1px 不齐？还是把文字行高改成 `21 + 4 + 16 = 41`？还是把头像改回 42px？（后者与 `--rail-avatar: 41px` 冲突）

### C3. `.tab` / `.rail-kb` 的 `background-size` 未跟随尺寸放大

`Round 198` 把 `.tab` / `.rail-kb` 的盒子从 34px 放大到 `var(--rail-avatar)` = 41px，
但 **`background-size` 仍是 34px 34px**（`.tab`）/ **22px 20px**（`.rail-kb`），且 `::after` 的 `background-size` 也未改。
- **需要决定**：位图图标是否随盒子等比放大？
  - 保持 34px / 22×20（当前生效值，图标视觉偏小、周围留白大）
  - 放大到与盒子匹配（例如 41px / 26×24）—— 但会拉伸位图
  - 保持现状并在 diff 中标注为「已知差异」
