## 0. 先说一个必须先对齐的关键事实：图标载体不一样

| | 原型 A | 本项目 React |
|---|---|---|
| 图标载体 | **位图 PNG**（内联 base64），靠 `background-size` 缩放 | **内联 SVG**（`viewBox 0 0 24 24`，`stroke-width:1.6`），靠 `--icon-size` 决定渲染尺寸 |
| 尺寸机制 | 方块 41px 固定，**位图尺寸独立**（34px / 22×20） | 方块 41px 固定，**SVG 满 viewBox 绘制**，`--icon-size` 直接 = 可见图形尺寸 |

**推论**：原型里"位图偏小"，在本项目里的等价问题不是"background-size 没用"，而是 **`--icon-size` 取值偏小**。而且本项目的 SVG 图形几乎撑满整个 `--icon-size` 盒子（实测 svg rect = `--icon-size` 本身），所以 **`--icon-size` 的 px 值 ≈ 可见图形直径**，可以直接和目标占比换算。

**本次实测（运行中的 React 应用，列0 四个图标全部相同）：**

| 元素 | 方块 | `--icon-size` | svg 实际 | 占 41px 方块 |

| 头像 `.wtRail__me` | 41×41 | 18px（文字） | — | — |
| 会话 `.wtRail__item` | 41×41 | **20px** | 20×20 | **48.8%** |
| 知识库 | 41×41 | **20px** | 20×20 | **48.8%** |

## 一、图标放大方案（待确认）

### 1.1 目标：把"参差"统一成一个协调的占比

原型的问题本质是**节奏不齐（63% → 82.9% → 53.7% 递减）**。既然本项目是 SVG（可自由定尺寸、不会被拉伸糊掉），我建议**不要复刻原型的参差，而是统一到一个中间偏高值**，让四个图标视觉重量齐平。

**推荐目标占比：68%**，即 `--icon-size: 28px`（41 × 0.68 = 27.9 ≈ 28px）。

选 28px 的理由：落在原型两个极端（53.7% 与 82.9%）的中间偏上，既不显空也不顶满留白；且 28 是整数，`svg` 渲染不产生半像素。

### 1.2 调整前后对比表

| 图标 | 载体 | 调整前 | 占方块 | **调整后** | **占方块** | 变化 |
|---|---|---|---|---|---|---|
| **会话/消息** | SVG | `--icon-size: 20px` | 48.8% | **`--icon-size: 28px`** | **68.3%** | +19.5pt |
| **知识库** | SVG | `--icon-size: 20px` | 48.8% | **`--icon-size: 28px`** | **68.3%** | +19.5pt |
| **插件** | SVG | `--icon-size: 20px` | 48.8% | **`--icon-size: 28px`** | **68.3%** | +19.5pt |

**四者统一后的关系**：头像 ≈63% / 四个图标 68.3% —— **基本齐平**，不再出现"越往下越空"。

### 1.3 对照原型（供你判断"忠于原型" vs "修正节奏"）

## 二、hover / focus 反馈方案（待确认，对应 C4 / C5）

### 2.2 本项目现状（已有 hover，但风格不统一）

| 元素 | 本项目 hover | 问题 |
|---|---|---|
| `.wtRail__me`（头像） | `translateY(-1px)` + `box-shadow: var(--wt-card-shadow)` | ⚠️ **上浮 + 大阴影**，是"卡片漂浮"语言，与列0 其他图标的"底色块"语言不一致 |
| `.wtRail__item`（四个入口） | `background: var(--wt-icon-hover)` + `color: → primary` | ✅ 与原型 `.rail-quick-add` 同语言 |
| `.wtSb__row`（智能体行） | `background: var(--wt-row-hover)` | ✅ 与原型 `.contact-item` 同语言 |

→ **已有的三套 hover 里，`.wtRail__me` 是个异类**（漂浮阴影 vs 底色块）。

### 2.3 建议方案：统一到「底色块」语言

既然你要求"参考其他已有 hover、保持风格一致"，而列0/列1 的既有语言就是 **`--wt-icon-hover` / `--wt-row-hover` 底色块 + 文字提亮**，我建议：

| 元素 | 建议 hover | 建议 active | 过渡 |
|---|---|---|---|
| `.wtRail__me` 头像 | **`background: var(--wt-icon-hover)`**（与四个入口一致）<br>~~去掉 `translateY(-1px)` 与 `--wt-card-shadow`~~ | `scale(0.96)`（保留现有） | `background/transform 260ms var(--wt-ease)` |
| `.hamburger` → `.wtRail__setBtn` 设置 | **`background: var(--wt-icon-hover)`** + `color: → var(--wt-txt-primary)` | `scale(0.96)` | `background/color/transform 260ms var(--wt-ease)` |
| `.wtRail__item` 四入口 | 保持不变（已符合） | 建议**补** `scale(0.96)` | 保持 |
| `.wtSb__row` | 保持不变 | 保持 | 保持 |

**统一后的视觉语言**：
- 所有列0/列1 的可点元素：**hover = 41px 方块内浮现 `rgba(255,255,255,.16)` 圆角底块，图标/文字同时提亮到 `--wt-txt-primary`**
- 按下统一 `scale(0.96)`，时长统一 **260ms**（= 既有 `--wt-dur-chip`）
- 不再有"上浮漂浮"这种与其余元素不同族的反馈

> ⚠️ 关于头像 hover 的一个取舍：现有 `translateY(-1px)+card-shadow` 是"可拖动/可点击的悬浮物体"语言，本身不算错。但你说要"与其他已有 hover 风格一致"，所以我按一致性优先建议**改成底色块**。如果你的本意是"头像保持漂浮感、只给设置补 hover"，请告知 —— 我改成保留头像原样。

### 2.4 :focus-visible（C5）—— 建议保留，且统一

原型全文**没有任何 `focus-visible` 样式**。本项目目前**已有** `box-shadow: var(--wt-focus-ring)`（`0 0 0 2px var(--wt-ring-stroke)`），分别落在 `.wtRail__me` / `.wtRail__item` / `.wtRail__back` / `.wtSb__iconBtn` / `.wtSb__row` / `.wtSb__del`。

**建议：全部保留，不删不改。** 理由：
1. 你明确要求"保留键盘 :focus-visible 焦点环，不要移除"；
2. 它只在**键盘 Tab 时**可见，鼠标点击不出现 → 不会污染截图 diff（GPU diff 用鼠标操作，focus ring 不触发）；
3. 删掉会失去无障碍，且不合你的要求。

**唯一建议的微调**：把焦点环统一为同一个 token（现在都是 `--wt-focus-ring`，已经统一），并**确保新增的"设置"按钮也带上**。
