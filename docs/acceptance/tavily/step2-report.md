## 三、误判情况：发现 → 根因 → 处置

### ①【已修】模型拿搜索去敷衍浏览器任务
- **现象**：`打开必应帮我查一下今天的美元汇率` 在模型层调用了 `web_search`，回答里还写了「已打开必应」，
  并且夹了一整句英文 `I'll open Bing and look up today's USD exchange rate for you.`
- **根因**：只靠工具描述约束不够，系统提示词里没有"这一轮你手边有什么/没有什么"的近因声明。
- **修法**：① 工具描述里补"点名网站时**绝对不要**调用本工具、也不要说已打开"；
  ② 新增 `chatSearchPolicyBlock()` 注入系统提示词（近因位置）。
- **复测**：模型层不再把搜索包装成网站操作（46 PASS/0 FAIL）；英文开场白也消失（新增"不夹整句外文"断言）。

### ②【已修 · 我自己引入的矛盾】两条提示词打架
- **现象**：我加的"你没有打开网站的能力、不许说已打开"与基座提示词的
  「用户说了『打开百度…』这类明确开页指令时，**网页卡片已经开好了**：直接说已经打开」**自相矛盾**。
- **根因**：没区分"这一轮桌面有没有报『网页已经开好』"（`browserOpened`）。
  「打开百度」这种**纯开页**指令走的是聊天路径**但带 `browserOpened`**，那一刻说"已打开"是**对的**。
- **修法**：`searchPolicyForTurn({ pageOpenedThisTurn })` —— **只在没开页的那一轮注入**。
- **防呆**：加了断言 `0.4 基座确实要求"纯开页指令直接说已经打开"`，
  证明这条闸**不是摆设**（基座那句话还在，所以这道闸必须存在）。

### ③【已修 · 测试自身的问题】三条错断言
| 问题 | 根因 | 处置 |
|---|---|---|
| 隔离自检把文件顶部"本文件不碰浏览器"的**注释**当成"引用了浏览器" | 静态扫描没剥注释 | 加 `stripComments()`，只扫**代码**；并补"编译产物零 require"这条硬证明 |
| `1加1等于几` 回答「1+1=2。」被判"不是中文" | 断言把"含中文"当成唯一判据 | 放宽：含中文 **或** 压根没有成词拉丁文（纯数字/符号无语言属性） |
| `帮我查一下"碳化硅"…` 期望写成"该搜索"，实测直接答了 | **我的用例设计错了**（工具描述里明确写"解释通用概念不要搜"） | 改成 `either`（搜不搜都对），**并把这段理由写进脚本注释**，而不是去调提示词把它"改成会搜" |

## 四、⚠️ 计划外需要决策的问题（两条，都在浏览器触发代码里）

### 问题 A（就是你最初描述的那类误判）：`detectBrowseIntent` 会把"帮我查一下X"当成"在当前页干活"
- **实测**：`detectBrowseIntent('帮我查一下今天的美元汇率')` → **命中**（返回原句）；
  `detectBrowseIntent('帮我查一下"碳化硅"主要用在哪')` → **命中**。
- **触发条件**：`App.tsx` 里 `browseGoal = openUrl === null && activeTab ? detectBrowseIntent(value) : null`
  —— 即**只要当前开着一张网页**，这句就会被交给驾驶员去动浏览器。
- **后果**：用户开着浏览器随口问一句"帮我查一下今天的美元汇率"，AI 会去**驾驶那张页**，
  而不是走轻量搜索 —— 正是"该走搜索却触发了浏览器"。
- **修的位置**：`apps/desktop/src/browser/intent.ts`（或 `App.tsx` 里那句 gate）—— **都是浏览器触发代码**。

- **修的位置**：`sites.ts` 的 `VERB` / `detectOpenUrl` —— **同样是浏览器触发代码**。

## 五、「回答语言」原则的落地

- 语言的来源只有 `language.ts` 一处，现在恒返回 `zh-CN`；
  以后加语言切换时**只改 `currentReplyLanguage()` 一个函数**，chat 路由与提示词拼装都不用动。
- 规则写死在系统提示词里：「**始终用系统当前语言回答**；不跟随提问语言，也**不跟随搜回来的资料语言**」。
- **实测**：`最近 OpenAI 有什么新消息`（资料多为英文）、`2026年诺贝尔物理学奖`、`特斯拉股价`
  —— 回答**全部是中文**，且没有夹整句外文。
- 为此**没有**写任何"搜索翻译"专用规则 —— 按你说的，那是这条通用原则的自然结果。

## 六、主观体验项（**需要你亲自打开应用看一眼**）

自动化只证明了"这条提示会被渲染出来"，**证明不了好不好看**。请重点看这几点：

1. **一行小字的位置/字号/颜色**：它出现在聊天气泡**上方**，12px 灰字 + 一道细左边线。
   你会不会觉得太淡（看不见）或太抢（比回答还显眼）？
2. **文案的节奏**：搜索时显示「正在搜索：今天有什么新闻」→ 搜完变成
   「已搜索「今天有什么新闻」（5 条结果），正在整理…」→ 本轮结束整行消失。
   **"已搜索…正在整理"这一句要不要留？** 不留的话就是搜完直接消失，界面更干净但少了"正在整理"的交代。
3. **长 query 换行**：如果模型拟的搜索词很长，这行会不会换行、换行后难不难看。
4. **会不会"闪"**：搜索很快（0.7~2.4 秒）时，这行字可能一闪而过。你介意吗？需要加一个最短停留时间吗？

### 行尾坑（复发）

现象是"注入点没找到"，**极易误判成"代码被别人改了"**。
修法：`patch()/unpatch()` 里按**文件实际行尾**归一化锚点再匹配。
（`*.ts/tsx/css` = CRLF、`*.py` = LF、`*.mjs` 验收脚本 = LF）
