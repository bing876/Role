## 一、审计方法（不是靠猜，是靠对 DOM）

1. 把桌面端 `apps/desktop/src` 里所有 `className` 抽出来，逐个到原型 HTML 全文里查 → 174 个查不到。
   但其中绝大多数是 React 的 BEM 命名（`__xxx`），**不能按类名判定**，会大量误伤。
2. 所以改用**运行时 DOM 比对**：原型 `.main-area` 里到底有哪些节点，逐行读 HTML 确认。
3. 判定标准只有一条：**原型 HTML 里有没有这个东西**。`grep` 计数为 0 的 = 自加项。

## 六、剩下的差异是什么

1.56% 的差异集中在三处，**全是图标字形**，不是几何尺寸：
- 列0（3.82%）：消息图标、知识库图标的字形与原型 base64 内联图标不完全一致
- 列1（4.59%）：联系人头像、搜索图标
- 输入胶囊（2.45%）：＋ / 麦克风 / 发送三颗按钮里的 SVG

要彻底归零，下一步是**把原型的内联 SVG / base64 图标原样抽出来替换桌面端的 `icons.tsx`**，
而不是继续调 CSS——几何尺寸已经对齐了，差的是图形本身。

## 一个"看着像 bug 但其实对"的点

实测消息 tab 是 **42×42**、图标 35×35，而原型标注 41×41 / 34×34。
不是错位：原型 `.tab.active` 自带 `transform: scale(1.02)`，
41×1.02≈41.8→42、34×1.02≈34.7→35。**选中态就该这么大**，未选中的知识库 tab 实测正好 41×41。
