## 1. 这一轮到底改了什么

上一轮的做法是「改 CSS 数值去凑原型」，方向是错的 —— 两边是**两个不同的骨架**。
本轮改为**照原型的 DOM + CSS 重写**，取值全部来自原型实测（`docs/acceptance/rewrite/proto-spec.md`）。

### 1.1 列0 导航轨（RailColumn.tsx + rail.css 重写）

| 原型选择器 | 桌面端类名 | 关键尺寸 |
|---|---|---|
| `.rail` | `.wtRail` | 宽 60px；`rgba(42,42,42)`；`blur(10px) saturate(120%)` |
| `.menu-btn`（顶部头像） | `.wtRail__me` | 41×41；r10；品牌渐变 `135deg #7c5cff→#4f8bff` |
| `.tab.tab-msg` | `.wtRail__tab` | 34×34；悬停用 `::before` 42×42 r14 方块淡入 |
| `#railKb` | `.wtRail__tab` | 同上，图标 22×20 |
| `.rail-quick-add`（＋） | `.wtRail__quickAdd` | 41×41；r10；白 10% 底 + 2px 55% 描边 |
| `.hamburger` | `.wtRail__settings` | 20×14；三条 2px 横线；`margin-top:auto` |

**关键点：悬停高亮是 `::before` 方块淡入，不是改按钮背景** —— 这是原型里
「图标底下浮起一块圆角方块」那个效果，之前一直没实现对。

### 1.2 列1 联系人栏（AgentSidebar.tsx + agent-sidebar.css 重写）

| 原型选择器 | 桌面端类名 | 关键尺寸 |
|---|---|---|
| `.sidebar` | `.wtSb` | 270px；`rgba(47,47,48)`；`blur(14px) saturate(128%)` |
| `.search-pill` | `.wtSb__searchPill` | 36px 高；r18；放大镜 `left:13` 18×18 |
| `.search-field` | `.wtSb__searchField` | `left:40 right:38`；16px；`line-height:36` |
| `.contact-item` | `.wtSb__row` | 高 56；r14；`gap:11`；`padding:0 12 0 8` |
| `.contact-avatar` | `.wtSb__avatar` | 41×41；r10；`color-mix(品牌色 16%, #fff)` |
| `.contact-name` | `.wtSb__name` | 16px / 600 |
| `.is-hen .contact-name::after` | `.wtSb__henBadge` | 10px；r4；「母」字 |

行间 1px 渐隐分隔线也照抄了（`.contact-item + .contact-item::before`）。

### 1.3 输入胶囊（App.tsx 的 `.inputBar` + styles.css）

原型的 `.inputbar` 是一颗 **47px 高、圆角 50px 的胶囊**：
`left:10 right:130 bottom:10`，`background:#2C2C2C`，`blur(8px) saturate(120%)`。

内部：附件 31×31 → composer（flex:1，`margin-left:7px`）→ 语音 40×40 →
发送 36×36（`rgba(255,255,255,.3)`，内含四角星 sparkle / 停止方块）。

上一轮是「方角输入框 + 发送/结束 两个按钮」，本轮换成原型的胶囊。

### 1.4 去掉浏览器区

- 删掉 `<BrowserPanel>` 的渲染与 import（`useBrowserWorkspace` 状态机**保持不动**，只是不渲染）
- 删掉「暂无浏览器任务」空状态占位
- 原型里 `browser` 一词只出现在 2 条 CSS 注释里，**根本没有这个区域**

### 1.5 悬浮玻璃卡片（本轮新增，用户选定）

原型是**一张浮在壁纸上的卡片**，实测：

| | 值 |
|---|---|
| 卡片外缩 | 左 24 / 上 13 / 右 23 / 下 13 |
| 卡片尺寸 | 1353 × 874 |
| 圆角 | 20px |
| 背景 | `linear-gradient(107.76deg, rgba(167,167,167,.10) -1.16%, rgba(133,133,133,.05) 100%)` + `blur(80px)` |
| 投影 | `0 14px 36px rgba(0,0,0,.32), 0 3px 10px rgba(0,0,0,.20)` |

桌面端用 `.wtApp`（壁纸层）+ `.wtFrame`（卡片本体）两层实现，三列放进 `.wtFrame`。

同时**修正了一个 32px 的错位**：原先给 `.wtApp` 加了 `padding-top:32px` 来避让
32px 的拖拽带（那是为 `frame:true` 的原生标题栏留的）。窗口已经是 `frame:false`，
这 32px 就变成纯死区，把列0 头像从原型的 y=32 推到了 y=46。现已：

- 拖拽带高度 32px → **14px**
- `.wtApp` 的 `padding-top` 32px → **0**
- 列0 顶部内边距按「卡片内 19px」设置 → 头像落回 **y=32（与原型一致）**

## 3. 还没对齐的（都是**内容/数据**差异，不是骨架）

| 现象 | 原因 |
|---|---|
| 头像里是字（助/卡/电），原型是彩色插画 | 原型用内嵌 base64 位图头像；桌面端用「字 + 品牌色底」 |
| 状态行「在线 / 已就位」，原型是「扫码绑定 OpenClaw 客户端」 | 桌面端填真实状态，原型写死文案 |
| 选中行不同（原型选中第 2 行，桌面端选中第 1 行） | 取决于当前选中哪个智能体 |
| 列2 消息区热力最红 | **原型这一列是空的**（Round 126 删了所有种子消息），桌面端有真实会话记录 —— 这是用户明确选择「保留桌面端的消息显示」的结果 |
| 右上「窗口按钮区」 | 用户已裁决「整条标题栏全去掉」，所以这里本来就该是空的 |
