# 桌面端自动拉起服务端 —— 换装校验结果 & 操作指南

## 一、这次换装装进去的是什么

让「**后端没起**」这件事从 **报错** 变成 **自动修好**。

以前：重启电脑 / 没跑 `npm run dev:server` → 桌面端停在登录页，红字
「连不上后端 http://127.0.0.1:8787」，得你自己记得去起服务端。

现在：桌面端启动时自己探测 8787，不通就**在后台把服务端拉起来**，等它就绪再开窗。

### 三条刻意的自我约束（不会打扰你原有的用法）

| 约束 | 说明 |
| --- | --- |
| **绝不碰你手动起的服务端** | 8787 上本来就有服务端 → 探测到就直接用，**不接管、退出时也不杀**。只杀自己 spawn 出来的那一个（靠 child 句柄判归属，不靠 PID 猜） |
| **起构建产物，不是 tsx** | 跑 `node dist/index.js`，不依赖 devDependencies 和源码目录。产物不在才退回 tsx |
| **失败不阻塞开窗** | 拉不起来就照常开窗、让登录页显示它本来那句红字（那是准确的），同时把真实原因写进日志。**不弹窗挡你**、不假装成功 |

想临时关掉自动拉起：设环境变量 `WORKBENCH_NO_AUTOSTART_SERVER=1`。

其中 5 条指纹是本次重点：

- `supervisor ELECTRON_RUN_AS_NODE 取 node` —— 防止拿 `electron.exe` 当 node 用

- `supervisor 起构建产物 dist/index.js`
- `main.js 调用 ensureServer 自动拉起`
- `main.js 退出时 stopOwnedServer 收尾`

## 三、你需要动手做的：只有一步

**双击桌面上的「AI 工作台」就行。** 不用再手动起服务端了。

（如果你想验证它真的生效：先把 8787 上的服务端全关掉，再双击应用 ——
登录页应该**不再出现红字**，直接正常进界面。）

### 想手动起服务端时（可选）

```bash
cd apps/server
node dist/index.js        # 注意要在 apps/server 目录里跑
```

> ⚠️ **必须在 `apps/server` 目录下运行**：服务端用 `dotenv` 从**当前工作目录**读 `.env`，
> 在仓库根跑 `node apps/server/dist/index.js` 会报
> 「缺少环境变量：DATABASE_URL、JWT_SECRET、DATA_KEY」。
> 自动拉起时我们就是带着 `cwd = apps/server` 起的，所以不会有这个问题。

## 五、真机验证结论

- **自动拉起**：日志
  `8787 不通，自动拉起：electron.exe + ELECTRON_RUN_AS_NODE=1 跑 dist/index.js（构建产物）`
  → `✅ 服务端已就绪` → `/health` 返回 `{"ok":true,"db":"up"}`。
- **不接管**：你手动起的服务端在跑时，38 ms 返回
  `8787 已有服务端在跑，直接用（不接管、退出时也不动它）`、`ownedByUs:false`，
  退出收尾打印 `没有自己拉起的服务端，无需收尾`，
  **监听 pid 从头到尾没变、`/health` 仍通**。
- **父子生命周期**：自动拉起的服务端随桌面端退出而退出（`code=143` SIGTERM），不留孤儿。

## 六、一个本机限制（不是 bug，但要告诉你）

本机（虚拟机环境）**不带 `--no-sandbox` 时 Electron 自己会崩**：

```
FATAL:gpu_data_manager_impl_private.cc(423) GPU process isn't usable. Goodbye.
```

进程一死，它 spawn 的服务端也跟着死 —— 所以「自动拉起」的效果要在
**应用窗口能活下来**的前提下才看得到。这是本机 GPU 沙箱限制，与本次改动无关。

**这意味着：真正好不好用，需要你在你自己的正常桌面环境上双击试一次**
（你那边应该不会撞到这个限制）。见下面第七节。
