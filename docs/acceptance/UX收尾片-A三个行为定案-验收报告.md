## 一、A 三个行为定案（已实施）

### A① 暂停画成非执行态

| 要求 | 实现 |
|---|---|
| 状态行「已暂停 · 说「继续」接上」 | `useChat` 分支 A（发「停」）里：清 `runningLoopId`（界面回非执行态）+ 把 loopId 存进新的 `pausedLoopIdRef`；`awaitResume` 三件套置位（**复用既有机制**，原来只有「步数上限」在用）→ App 派生 `pausedHere` ⇒ 状态行换成 `.runStatus--paused`（⏸ + 「已暂停 · 说「继续」接上」） |
| 输入框回正常发送 | 发送键单列「暂停态」分支（**否则会落进「打字中…」并被禁用** —— 挂起时 `streaming` 仍是 true）；暂停态不再画打字光标 |
| 下一句「继续」原地接上 | **「继续」的判定块整体上移到 `sendChat` 最前面**（原来它在「有循环」分支之后 ⇒ 挂起时根本走不到）；命中后走既有的 `resumeTask(wcId)`（先读真实页 → 服务端解挂 → 原地接上），并把 loopId 接回 ⇒ 状态行回到「执行中」 |
| 不弹横幅 | 「停」不再写那行 chatNote（状态行已经把话说清楚） |

### A② 状态行钉在输入框正上方（紧凑一条）

状态行整块从 `.chat` **搬出**，成为 `<main>` 里输入框的**前一个兄弟节点**（两行间距 → 一行紧凑）；
轨迹抽屉放在状态行下面（`<details>`，默认收起），点开才占地方。

### A③ 补充时状态行瞬态「已收到补充」

补充注入成功 → `useChat` 调 `onSupplementAccepted()` → App 在状态行里插一个 `.runStatus__ok`「已收到补充」，
**2.5 秒**后由定时器收掉（CSS 只做淡入淡出动画）；**没有任何横幅**。
