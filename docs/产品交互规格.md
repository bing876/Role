# 产品交互规格(阶段 2)

> ★ **本文档是所有后续会话都要读的产品标准**。它定义「用户只管委派,界面越少让用户操心越好」在交互上长什么样。
> 判据(继承《智能体协同-总计划》):「这帮用户委派了,还是又多给他一件事管?」
> 定稿:2026-09-25(用户原话八条)。对齐依据:`docs/智能体协同-总计划.md`。

## 一、八条核心标准(逐条必须满足)

### C1 创建智能体

说「建/创建 XXX」→ **立刻建好、左栏出现真名字**;三问变**输入框上方一行 chips**(可点 / 可自己写 / 可跳过),**无大表单、无确认框**;打字 / 跳过 / 答完**即消失**。

- 对齐:批次 L 已做后端(自然语言建 `agent_routines` + 一句话回话);智能体身份的「那一行问题 UI」总计划里明确**留到阶段 2** —— 即本条。
- 验收口径:界面里发「创建 XXX」→ 左栏立刻出现真名字(真库真数据,非写死);三问以输入框上方一行 chips 呈现(每条可点选 / 可改 / 可跳过);答完或跳过,chips 消失;全程无大表单、无确认框;新建智能体落真库可查。

### C2 第四列

点**会话链接**或「**启用**」才弹出;左拖**盖住聊天**;**隐藏 ≠ 卸载**(回来不重载)。

- 对齐:用户第四列拍板(三形态 / 双触发 / 隐藏 ≠ 卸载 / 显式 `--update-golden`);「AI 开页不自动弹列」的判断保留。
- 验收口径:`verify:shell`(webview 祖先链 golden、切视图/切智能体不换元素、隐藏 = `transform` 移出视野而非 `display:none`)+ `verify:column:revert` C1–C5 反证;点会话里的链接与点「启用」两个触发各自能弹列;回来不重载(webview 同一元素)。

### C3 GrokBot 无感

**不给用户增加管理动作**;**头像即状态**;协同**进对话流**(折叠);**没有仪表盘 / 指派板**。

- 对齐:总计划「Grok 的取舍」段 —— 主对象是 Bot 不是对话;头像即状态(idle/thinking/working/waiting/blocked/done),不做一堆指示器;砍掉仪表盘/指派板/手动交接;协同往来进对话流、折叠成一行摘要。
- 验收口径:左栏头像直接承载状态;委派/交接/催办等协同事件以折叠摘要行出现在对应会话流里;界面里不存在独立仪表盘/指派板入口。

### C4 记忆

**要确认才生效**,但确认**在对话流里**,不弹抽屉。

- 对齐:记忆四批之「确认卡 UI」(bf4a05e)。
- 验收口径:记忆候选 → 对话流里出现确认卡(点确认才进 `memories` 真表);不存在抽屉式确认组件;拒绝/忽略同样在对话流里完成。

### C5 聊天

**流式逐帧**;失败进**红槽 / ⚠**,成功进普通槽。

- 对齐:F2-③ 双提示槽(成功槽/失败槽拆开,`7f97699`);logic `★F2-③` 断言 + P5 反证 + shell ⑭-3。
- 验收口径:SSE 逐帧渲染(不是整段弹出);失败进专门红槽/⚠ 且成功槽保持干净;成功进普通槽。

### C6 登录

「**检查中**」与**真登录页**两种样子。

- 对齐:F4 拆 `.authWrap--checking` / `.authWrap--login`(`c8507fe`);logic ⑬-1 + modal 反证 M2(占位页退回裸 `.authWrap` → 红)。
- 验收口径:启动先出「检查中」态;无 token / 失效才出真登录页;两态类名不同、外观不同(一名一义)。

### C7 定时任务

**建完回一句话,不是确认框**。

- 对齐:批次 L · L2 —— 名册精确解析(不偷偷挑最像的)/ 去重(已有 active 回「已经有一个了」)/ `createRoutine` 真建 / **一句话回话**「已设成:X 每天 09:00 任务,结果发这里。」(结果去向不撒谎)。
- 验收口径:自然语言定时任务 → `agent_routines` 真表落行 + 会话流一句话;无确认框;重复建不建第二个。

### C8 委派

**@ 规则五条**;**不偷偷换人**;**折叠摘要**。

- 对齐:批次 J(解析器单一实现 `packages/shared`):
  ① `@` 必须紧跟名字;② 只第一个命中当发言人,其余进 meta;③ R-A 被点名者忙/等 → 不静默改派,回「它在做什么 + 要不要等/换人」(且不让正忙的那个替自己开口);④ R-B @ 的就是当前发言人 → 视作没写 @;⑤ R-C 交给模型的正文剥掉 `@名字`(库里存原文);只写了 `@名字` → 不调模型、反问。
  拍板:per_round(`@` 只换这一轮谁开口)+ allow_with_owner(点名轮照样能进工具循环,循环主人不换)。
  换人轮在气泡挂名字牌;协同进对话流的折叠摘要与 C3 同一条线。
- 验收口径:批次 J 四层(解析器 / 决定层 / 渲染层 / 真机端到端)+ 反证 M1–M8;界面上不出现「已改派给 Y」这类偷偷换人。

## 一·补、人设模型(G2, 2026-09-25 用户定)

人设(`AgentPersona`)从四格扩到六格,两条**必须满足**的规矩:

### G2-1 描述 = 整份人设

智能体的 `description` 栏**就是完整人设正文**(路由燃料 + 审批边界),不是被截断的摘要。
建号/建人时给的整段人设描述,原样进这一栏;拼系统提示词时整段注入,不裁剪。
- 验收口径:`GET /agents/:id/persona` 读回的 `description` 与写入的整份人设逐字一致;`buildIdentityBlock` 注入的提示词里含这段全文。

### G2-2 每个 agent 增「不干什么」标准栏

`antiJobs`(不干什么 / anti-jobs)是**每个智能体的标准栏**:创建 chips、人设编辑表、
`POST /agents/:id/persona`、`detectBuildIntent` 落库链路都支持填它;拼系统提示词时
作为「不干什么」一行注入(空则跳过)。
- 验收口径:chips 有一组「不干什么」可点/可自己写/可跳过;填了 → 落库 + 提示词注入 + 读回一致;不填 → 保持空、不报错。

### G2-3 小助默认身份(Eggbot 配置)

自带「小助」建号即带**用户给的「小助配置」**作为默认身份 + 描述(是谁 / 怎么说话 /
干什么 / 不干什么 / 整份人设),`persona_status=ready`。存量账号(小助 persona 为空)
由启动迁移回填同一份默认(只补 NULL,绝不覆盖用户改过的)。
- 验收口径:新账号小助 `GET /agents/:id/persona` 读回 = 整份人设(含 description 全文 + antiJobs);小助的系统提示词含「管家/总协调」身份与「不干什么」;存量账号重启后小助人设不再是 NULL。

## 二、QA 循环方法(用户定)

1. 起**真服务端 + 可用 DB**(`VERIFY_DATABASE_URL`,embedded PG),把每条标准当**真实用户**从界面/接口走到尾,记录「标准 vs 实际」。
2. UI 层:jsdom 挂整个 `<App/>` 走真实路径(不装 headless Chromium;验收 = CSS 断言 + jsdom 行为断言 + webview 祖先链 golden)。API 层:真服务端真端点,查真库。
3. 不一致 → **直接改代码**(UI 或逻辑都可以;与标准相悖的旧代码直接换,例如移除大表单),改完**重跑该条**;全部一致才停。
4. 每个修复带**验收 + 反证 + 立刻 push**(铁律不变)。
5. **红线(冲突就停下报告,不许硬改)**:浏览器不卸载 / 不 `display:none` / 不归零;库不存明文(fail-closed);不删工作(禁 `git clean` / `reset --hard`);不开 / 合 PR;留在自己分支。
