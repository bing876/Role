## 1. 🔴 阻塞

### R1 · 聊天搜敏感信息直传第三方（新）—— S1 实锤

| 项 | 内容 |
|---|---|
| 位置 | `apps/server/src/search/chatLoop.ts`、`chatTool.ts`（chat 路径 `web_search`）；对比：loop 路径 `toolLoop.ts` 有敏感闸，chat 路径**没有** |
| 现象 | 聊天里问「银行卡尾号8888是哪家银行的卡」→ **原文 verbatim 发给 Tavily**，1 次搜索，零拦截、零提示 |
| 证据 | `s1-search-sensitive.mjs`：Tavily 桩收到原查询；同句式走 loop `type` 则被拦（`ask`/`sensitive_field`），证明**只有 loop 有闸** |
| 影响 | 用户 PII（卡号/身份证/手机号…）在用户无感知时发往第三方搜索商；日志里还会再记一遍（`本轮联网搜索…${s.query}`） |
| 修复建议 | 复用服务端同一套敏感正则：在 `web_search` 执行前判一次，命中→转 `ask` 或拒绝并提示用户改问法；日志中的 query 做脱敏 |

### R2 · 敏感输入值明文落库（新）—— S6-D + 记账链实锤

| 项 | 内容 |
|---|---|
| 位置 | `apps/desktop/electron/agent.ts` `label()`（步摘要）→ `taskStep` → `POST /agent/task/step` → `tasks.payload.steps`（**JSONB 明文**，`db.ts:121-131` 只有 `result_enc` 加密） |
| 现象 | `type(target=备注, text=我的密码是Secret123)` → 步摘要「在「备注」输入「我的密码是Secret123」」→ 原文进 emit（界面）+ 任务表 + 收尾文档兜底 |
| 证据 | `s6-agent.mts` D 节：密码原文出现在 `taskStep` 摘要与 emit 中，`true`；服务端闸只查 `target` 不查 `text`，良性框名 + 敏感值**全程无闸** |
| 影响 | 密码/验证码/卡号躺在 Postgres 明文字段（含备份）；`chat.ts` 日志、`notify` 日志亦可能携带 |
| 修复建议 | ① `label()` 对 `text` 只记长度/掩码（如「输入了 12 个字符」），绝不记原文；② `/task/step` 服务端再加一道敏感正则清洗；③ 存量 `payload.steps` 考虑加密或清理策略 |

### R3 · 暂停吞回执 → 继续必重执行（新）—— S7 实锤，确定性复现

| 项 | 内容 |
|---|---|
| 位置 | `apps/desktop/electron/agent.ts`：`pauseOut()` 与 `aborted()` 返回时**丢弃已算好的 `result`**（局部变量，不落盘不发送）；服务端 `toolLoop.ts` 无回执则断言「工具没有被执行」并重判 |
| 现象 | 第 1 程：`next→click(提交)→exec 完成→暂停`（回执被吞）；`/resume` 后第 2 程：服务端重发同一 `click` → **「提交」被执行 2 次** |
| 证据 | `s7-double-exec.mts`：真服务端 + 真 `runToolLoop`，`exec 总次数: 2`，两次 `{"action":"click","target":"提交"}`；触发窗口 = exec 完成 → 下一次 `/next` 之间按暂停（用户看到步骤完成提示后按暂停即命中） |
| 影响 | 提交/下单/发送类不可逆动作被执行两次；且服务端话术把责任推给执行端（「工具没有被执行」），排查会被误导 |
| 修复建议 | ① 暂停/中止前**先把 pending 回执刷给服务端**（随 `/pause` 附带 `result`，或新增 `/note` 回执口）；② 服务端改话术为「回执缺失」，恢复后先 `read_page` 核验再定是否重做；③ 长远：按 `(loopId, callId)` 做执行台账（幂等键） |

| 证据 | `s5-known-reverify.mjs` P0-1b；代码规则确认：问候/短概念问才走聊天，其余中长句全发车 |

### #6 · `done` 集合整体 `clear()`（P1，复验：仍开）

位置 `apps/server/src/routes/memories.ts:369`。800 条一满全清 → 已抽取过的会话被重复抽取（重复 LLM 费 + 重复记忆）。
修复：按 key 淘汰最旧（如只删前 100 个）或 LRU。

### 怀疑4 · `hijack()` 后仍走 `dbErr(reply)`（P1，复验：仍开，两分支）

位置 `apps/server/src/routes/chat.ts`：hijack 点 `:392`（任务分支）/`:539`（聊天分支），外层 catch `:660` 无条件 `dbErr(reply)`。
窗口（已收窄但未消除）：hijack 成功后、`sse(...)/res.end()` 抛错（如客户端恰好断开）→ 外层 catch → Fastify 抛 "Reply was already sent"，**真因被掩盖**；任务分支还会额外留一个孤儿循环 + 历史里一句没下文的开场白。
修复：立 `hijacked` 标志位，hijack 之后只写 SSE + 打日志，绝不碰 `reply`。

### R5 · P0-3 搜索兜底静默改道（复验：机制仍在，S6-A 实锤）

位置 `apps/desktop/electron/agent.ts`（`type` 失败 + 目标/goal 含关键词 → `open_url` 百度）。
证据：`type(target=密码)` 找不到框 → 直接开百度搜结果页，**无任何敏感申报**；密码值本身未被填出（只开了 URL），所以后果是「行为分叉 + 漏申报」而非「填错地方」。
前置条件较窄（需先过服务端闸+页内闸），故列高而非阻塞。
修复：兜底前对 `target` 再做一次敏感判定；敏感目标宁可 `ask` 也不要静默改道；`searchKeyword(goal)` 进 URL 前脱敏（goal 里若有敏感词会进百度 URL）。

### R6 · `/next` 传输出错即永久杀循环（新）—— S6-C 实锤

位置 `apps/desktop/electron/agent.ts`：`next()` 抛错 → `finish('brain_failed')` → `stopLoop`（终态）。
证据：`next` 抛 `fetch failed` → 返回 `brain_failed` + `stopLoop:['ended:brain_failed']`。
影响：服务端 10 秒保活能自愈重启，但循环已被杀（内存态丢失也一样），单次网络抖动 = 任务永久失败；与「保活自愈」设计相互打架。
修复：传输出错（fetch 超时/5xx/ECONN）加退避重试（3 次）；区分「传输错」（可重试，不杀循环）与「逻辑错」（4xx/loop_gone，走现有卡片）。

### R7 · `pageState` 跨租户串扰（新）—— 代码实锤

位置 `apps/server/src/pageState.ts`：`pageStateOf()` 按 `wcId` 取条目，**不校验 `userId`**（注释写「只回自己的」，代码没做）；`clearPageState` **零调用方**（关页不清）。
影响：同一服务端 + 多用户桌面时，Electron 小整数 `wcId` 极易碰撞 → A 的 `current_task`/`last_page_summary` 被 B 读走并互相覆盖写。
修复：`found.userId !== opts.userId` 时当不存在（重建）；`loadPageState` 加 `userId` 参数；关页/循环结束调 `clearPageState`。

### R8 · 模型挂死 90 秒零反馈 + `failed` 终态（新）—— S3 实锤

位置 `apps/server/src/toolLoop.ts:930`（`timeoutMs: 90_000`）。
证据：kill 场景 11ms 即 `ask/llm_unreachable`（优雅 ✓）；hang 场景**整整 90 秒冻结**（无心跳无进度）→ 同样 `ask` + 循环 `failed` 终态（必须重开），且英文原文错误透传给用户。
修复：`advance` 期间发 SSE 进度注记（「模型思考中…」）；超时改短 + 重试一次；`llm_unreachable` 改 `waiting`（可继续）而非 `failed`。

### R9 · 无 LLM 费用熔断（新）—— 700-call 实锤

证据：桩忽略 `tool_choice:none` 时，`chatLoop` 45 秒打了约 700 次 LLM 调用（桩的错，但证明**服务端无任何上限**）；`/chat/stream`、`/agent/loop/next` 全无线流（限流器只在短信口）。
影响：跑飞的客户端/模型 = 无底洞烧钱；且与 R4 联动（句句发车放大消耗）。
修复：`chatLoop` 加 `MAX_ROUNDS` 硬上限；按用户/循环加每分钟 LLM 调用配额；超配额回 429 + 人话。

### R10 · 敏感等待永不自动恢复（新）—— 代码实锤

位置：`agent.ts` 定义了 `sensitiveHold` 钩（契约写「实现方负责启动自动恢复观察」）但**从不调用**；`main.ts` 的 `sensitiveNotice` 只聚焦 + 发卡，不起 watcher；watcher 只在求助卡片（验证码/登录）路径启动。
影响：最常见的服务端敏感拦截（密码框/支付确认）退出后，用户输完必须**手动点继续**，「输完自动走」不成立；`lane.awaiting` 只有 UI/路由消费，无轮询。
修复：`ask` 分支 `await hooks.sensitiveHold?.()`（兑现契约）+ 补怀疑 2 的 watcher 叠加防护；或 main 在 `ask_user` 落定后起一次性 watcher。

## 4. 🟢 低 / 备注

- **pageDelta query 误判 moved**：`normUrl` 不去 query，筛选/分页改 query 即被判「换了一张页」。建议忽略 query 或白名单关键参数。（`pageDelta.ts`）
- **`events.jsonl` 无 prune**：`resource-guard` 只清 `samples/raw-*`，`events.jsonl` 常年累积（有 5 分钟冷却兜底，日增有限）。顺手加按月切分。
- **`/next-action` 超时文案 90s vs 实际默认 60s**：`agent.ts:153` 文案与 `llm.ts:217` 默认不一致，改文案。
- **注释与代码不符**（`agent.ts`「执行后查暂停」实际只查 `aborted`）：改注释。
- **P2-2 `staleClicks` 被 `read_page` 清零**（`agent.ts:~580`）：机制仍在，连点保护难触发；列低（有 FAILS_BEFORE_ASK 兜底）。
- **桌面退出时任务 SSE 不收**：`before-quit` 只停自起服务端；外置服务端上的任务长连晾到循环 TTL（10 分钟）。影响小（TCP 保活会先掐），备注。
- **服务端重启 = 循环全失忆**（by design，内存 Map）：有 `loop_gone` 确认卡承接（见 §5），备注为「已接受」。
- **WRAP_PROMPT 靠提示词禁敏感**（`agent.ts` 收尾整理）：模型可能不听；输出再加一道正则清洗。低。
