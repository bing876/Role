# 设计方案：让 ref-guard 钩子的安装**不依赖人记得**

> 状态：**待你确认后实施**
> 关联：`docs/方案-git-ref自动防呆-20260920.md`（守卫本体，已实施）

---

## 一、要解决的问题

守卫本体（`scripts/git/ref-guard.sh` + `hooks/`）已经**随仓库版本化**了，
但**让它生效的那一行配置**（`git config core.hooksPath`）**不进版本控制**。

→ 换电脑、重新克隆、或配置被重置之后，钩子**静默失效**，
  而人不会知道 —— 直到某次提交丢了 ref 又没检查，代码就真丢了。

---

## 二、方案：**两层，缺一不可**

### 第 1 层（主）：`package.json` 的 `postinstall`

```json
"postinstall": "node scripts/git/install-hooks.mjs --from-postinstall"
```

`npm install` 之后自动跑，覆盖主路径：**克隆 → npm install → 开始干活**。

**必须遵守的约束（否则会帮倒忙）**：
- **永不阻断 `npm install`**：npm 里 `postinstall` 非零退出会让整个 install 报错。
  → 脚本内部包一层 try/catch，任何异常都 **exit 0** + 打醒目警告。
- **幂等**：重复安装不报错、不重复写配置。
- **非 git 环境静默跳过**（tarball、CI 里没有 .git）：直接 exit 0。
- **装上了要说一声**（打一行），否则下次又没人知道它存在。

### 第 2 层（兜底）：`start-dev.cmd` 的「0) 自检」

启动时检查 `core.hooksPath` 是否指向本仓库的钩子目录：
- **不在 → 自动装**（顺手，不打扰）
- 装不上 → **醒目提醒**（红字 + 给出手工命令）

**为什么不能只做第 1 层**：
- 有人 `git clone` 之后**直接双击 `start-dev.cmd`**（依赖已装好，没跑 npm install）；
- `core.hooksPath` 被别的工具/配置覆盖或清掉；
- 第 2 层正好覆盖这些"postinstall 够不着"的场合。

**为什么不能只做第 2 层**（你提的退一步方案）：
- 纯命令行 / CI 里提交不经过 `start-dev.cmd`，那就漏了。

## 三、实施清单

| 文件 | 动作 |
| --- | --- |
| `package.json` | 加一行 `postinstall` |
| `scripts/git/install-hooks.mjs` | **新增**：Node 版安装器（`--from-postinstall` 时永不失败、静默降级） |
| `scripts/git/install-hooks.sh` | 保留（手工用 / 别的平台），两者共用同一份判断逻辑 |
| `start-dev.cmd` | 「0) 自检」里加一段：检查 + 自动装 + 装不上则红字提醒 |
| `scripts/verify/hooks-autostall-probe.py` | **新增**：验证探针（见下） |

> 保留 `.sh` 而不是只留 `.mjs`：`postinstall` 用 Node 更稳（不依赖 PATH 里有 sh），
> 但手工安装/其它平台用 sh 更直接。两者都只是薄壳，真正的判断逻辑只有一份。

## 四、验证方案（你要求的"模拟一次钩子没装"）

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | **`git config --unset core.hooksPath`**（模拟没装）→ 跑启动检查 | **检测到 + 自动装回** |
| 2 | 模拟 `npm install` 触发 `postinstall` | 钩子被装上、`core.hooksPath` 指向正确 |
| 3 | 连跑两次安装 | **幂等**：第二次不报错、状态不变 |
| 4 | 在**非 git 目录**跑安装器 | 优雅跳过、退出 0、不报错 |
| 5 | 把钩子目录改名（模拟文件缺失） | 检测到异常并给出可操作的提示 |
| 6 | **反证**：把"检测 hooksPath"那步关掉 | 场景 1 **必须变红** |

**外加真机演练（最有说服力的一条）**：
1. `git config --unset core.hooksPath`（真的把钩子卸掉）
2. **做一次真提交** → 确认 ref **真的丢了、且没人修**（`git log` 报 fatal）
   —— 这一步**证明"没装的后果"是真实的**，不是纸上推演
3. 跑启动检查 → 自动装回
4. 再提交一次 → 确认**自动修复又生效了**
5. 手工恢复第 2 步丢的 ref（用既定办法）

## 五、需要你确认的点

1. **`postinstall` 这个方向**可以吗？（它会在 `npm install` 时自动跑一个本地脚本）
2. `start-dev.cmd` 里做**自动装**（而不是只提醒）可以吗？
   —— 我倾向自动装（少一次打扰），但如果你希望"只提醒、由人决定"，我就改成只提醒。
3. 装上了要不要**每次启动都打一行**？
   —— 我倾向**只在"这次装上了"时打**（正常情况完全静默），避免噪音。
4. 要不要顺带把 `npm run hooks:install` 也加成一个 npm script，方便手工调用？
