## 片 3 · `app/browserGlue`（跨 chat × browser 的胶水）

推：`e7c96a9`（remote head，已 `ls-remote` 确认）

### 为什么单独一层

这三样东西**同时**属于聊天与浏览器两侧：

| 东西 | 聊天侧的一面 | 浏览器侧的一面 |
|---|---|---|
| 求助卡 `helpCards` / `curHelp` | 卡片长在聊天流里，按**智能体**分桶 | 触发时要把 `browser.view` 切到 `embed`（露出那一张页） |
| 「上下文没了」`loopGone` | 画在聊天区上方的确认卡 | 决定通过 `loopGoneChoice(wcId, …)` 回主进程 |
| 窗口几何 `embedRect` | HelpCard 每帧量一次、上报 | 交给 BrowserPanel 写进那个**一直挂着的** webview 的内联样式 |

放进任何一侧的 feature 都会形成 `features/A → features/B` 的横切依赖 —— 所以按用户拍板归 **`app/`**：
`apps/desktop/src/app/browserGlue.ts`（`useBrowserGlue`）。

> ★ **形态说明（要跟用户对一下）**：拍板写的是「`app/BrowserGlue` **Provider**」，
> 但本阶段铁律是「JSX 一行都不许动」，而 Provider 必须在 JSX 里加一层包裹 ——
> 所以这一片先落成**同名 hook**（对外契约就是这一份 `BrowserGlueApi`），
> 等阶段 2 允许动 JSX 时原样翻成 Provider 即可（`features/**` 不许依赖 `app/**` 这条已经满足了）。

### 搬了什么（只搬逻辑；JSX 35615 字符、CSS md5 都没变）

- `loopGone` state + `answerLoopGone`；
- `helpCards` state + `curHelp` + 那个「切智能体时跟着切视图」的 effect（含 `exitEmbed` 那条**真机时序破口**的注释与写法）；
- `embedRect` / `onEmbedRect`；
- `helpCardAct`（两个按钮走 `resumeTask` / `agentDrop`）；
- 给主进程事件分发用的三个写入口：`showHelp` / `clearHelp` / `clearEmbed` / `askLoopGone`（`clearHelp` 保留原来的「没有就别造新对象」引用稳定守卫）；
- `HelpCardView` 类型从 App 移到本文件并导出。

**App 侧只改三处调用**（名字全部没变）：
`setHelpCards({...})` → `showHelp({...})`；两处 `clear` 分支 → `clearHelp(ownerAgent)` + `clearEmbed()`；
`setLoopGone(…)` → `askLoopGone(p.wcId, p.question)`。

### ★ 本片最值钱的一条：反证抓到一个**假绿**

我先写的 hook 级断言只看 `browser.enterEmbed/exitEmbed` 的调用序列 —— 结果注入
「`curHelp` 改成 `Object.values(helpCards)[0]`（**跨对话泄漏**）」
时**验收网全绿通过**（假绿！）。原因：那个 effect 是直接读 `helpCards[curAgentId]` 的，
`curHelp` 只影响**渲染**，而我的 Host 当时 `return null` —— 渲染结果没人看。

修法：让 Host 把 `curHelp` **渲染出来**（`卡:4242` / `没卡`）并断言 —— 现在注入立刻变红：
`97 号的求助卡漏到 98 号对话里了：卡:4242`。
**教训：只断言副作用（函数被调）会漏掉"值算错了"这类抽错，能渲染出来的东西就要渲染出来断言。**

### 验收（`npm run verify:logic`：12 → 17 PASS / 0 FAIL）

新增 5 条：

1. 主进程 `help` 事件 → `.helpCard` 出现在 DOM，问题/提示文案与 `helpCard--captcha` 都对；
2. 点「我处理好了，继续」→ `resumeTask(4242)`（**唯一**一次调用）、卡片立刻收起；
