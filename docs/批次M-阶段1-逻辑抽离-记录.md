## 片 2 · `features/memory`（两层记忆 + 待确认）

推：`7bc05ce`（remote head，已 `ls-remote` 确认）

### 搬了什么（只搬逻辑，一行 JSX / 一行 CSS 都没动）

| 类别 | 内容 |
|---|---|
| 6 个 state | `userMem` / `userMemOpen` / `projMem` / `projMemOpen` / `pendingMem` / `pendingMemOpen` |
| 3 个读 | `loadUserMemory` / `loadProjectMemory` / `loadPendingMemory`（含 `memHeaders` + 项目切换/切号守卫） |
| 5 个写 | `forgetEntry` / `confirmMemory` / `rejectMemory` / `confirmAllPending` / `rejectAllPending` |

新文件：`apps/desktop/src/features/memory/{useMemory.ts,index.ts}`。

### 手法与陷阱（可复用）

1. **仍然「只换来源、不改名字」**：hook 返回的对象在 App 里**同名解构**（`user: userMem` 等），
   所以 `loadAgents` / `selectAgent` / `tidyCurrentAgent` 以及 5 处 JSX 调用点一个字都没改。
2. **★ 陷阱一：`sessionRef` 声明顺序。** 它原先声明在 memory 逻辑块**之后**（第 8 步任务快照那段），
   过去只在函数体里被延迟引用（`memHeaders()`），声明顺序无所谓；
   现在 hook 调用要在**渲染期**读它 → TS2448/2454。
   解法 = 把 `const sessionRef = useRef(...)` 上移到会话 state 之后。
   **移动 `useRef` 的位置不改变 hook 稳定性**（仍无条件、每次渲染同一顺序），且**没删任何镜像 ref**。
3. **★ 陷阱二：`onNote` 注入，`setChatNote` 留在 App。** `setChatNote` 另有 3 处非记忆用途（启动提示等），
   因此 memory feature **不许**去拿 chat 的 state；它只接收一个 `onNote: (t: string) => void`。
   这样 `features/memory` 对 `features/chat` 零依赖（feature 间只经 `index.ts`、更不许反向依赖 App）。
4. `forgetEntry` 的 `layer` 收窄成 `'user' | 'agent'`（App 传的是字面量，零风险）。

### 验收（`npm run verify:logic`：7 → 12 PASS / 0 FAIL）

新增 4 条走**真实 UI 路径**的行为断言（第二遍挂整个 `<App/>`，点按钮、看请求）：

- 三个入口显示服务端条数（用户 2 / 项目 1 / 待确认 2）；
- 展开用户记忆列出两条，「忘掉」发 `POST /memory/forget` 且 body 逐字段等于 `{layer:'user', id:301}`；
- 待确认点「确认」→ `POST /memories/confirm` body `{ids:[321]}`、**该行立刻消失**、聊天流回一句人话；
- **hook 级**守卫（直接挂真 hook，不是副本）：`curAgentRef` 从 97 切到 98 后，97 号的慢响应**不许**写进 `project`。

> 验收网里踩到的两个坑（以后写网要记得）：
> ① 记忆入口整个在 `{curAgent && (…)}` 里 —— 必须先让 `loadAgents` 成功、有当前智能体；
> ② 上一节「登出」断言会真的 `localStorage.removeItem('workbench.token')`，
>    第二遍挂 App 前必须把登录态放回去（`setItem`），否则会停在登录页 → 记忆入口永远不出现。

### 反证（`app-logic-smoke-revert.py`：4 → **7/7**）

脚本已扩成**多文件**（`mut['file']`），新增 3 处注入：

| 编号 | 注入 | 咬住它的断言 |
|---|---|---|
| M1 | `loadProject` 删掉「切走之后晚到的响应不能覆盖」守卫 | 切走智能体后不许覆盖 |
| M2 | `confirm` 去掉本地过滤（等服务端重拉） | 确认后该行立刻消失 |
| M3 | `forget` 的 body 少送 `id` | 忘掉的 body 逐字段 |

每次注入后跑完立刻还原，`md5` 逐字节一致。

### 顺手修的一条**假红**（不是放宽，是改指向）

`scripts/verify/mem-merge-batch4.mjs` 里有 3 条**位置型**断言：在 `App.tsx` 里 grep
`/memories` `/memories/confirm` `/memories/reject`。代码搬进 `features/memory/useMemory.ts` 后它们必然假红。

处理：**只改指向、不放宽** —— 现在扫的是真正的归属文件 `features/memory/useMemory.ts`，
并且要求「端点字符串」与「本行的 fetch 调用」**同时成立**（兼容 `authFetchJson<泛型>(` 写法），
比原来「文件里出现过这个字符串」更强。三条都通过。
