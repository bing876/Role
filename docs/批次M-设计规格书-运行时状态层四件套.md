# 批次 M · 设计规格书：「AI 运行时状态层」四件套（一起拍）

> 你选了「状态层四件套作为一个整体一起拍」。这份是**给你画图用的规格**：
> 每件写清 **① 什么时候出现、② 有哪几种态、③ 现在长什么样（DOM/类名/文案）、
> ④ 必须保留的可辨识度**（这是功能底线，不是审美偏好）。
> 规格里的事实全部来自当前代码，可逐条核对。基线 `151ec8b`。

## 0. 为什么这四件必须一起拍

它们回答的是同一个问题：**「此刻 AI 到底在干什么、卡在哪、要我做决定吗」**。
四件里的任何一件单独出现都会误导：
- 只有「头像状态圈」→ 看不出卡在哪一步；
- 只有「任务卡」→ 看不出这是"等你"还是"它在忙"；
- 只有「黄条」→ 用户已经摊在别的对话里了才看到一个突兀的确认框。

设计基准 `workbench-ui` 里**完全没有这一层**（它是纯聊天原型）。所以这四件是**新增视觉语言**，
建议：一套颜色语义（运行中 / 等你 / 出事了）+ 一套容器形态（条 / 卡 / 圈），四件复用同一套。

## 1. 「谁在等谁」状态条 ｜ `.driveState`

| 项 | 内容 |
|---|---|
| 位置 | 聊天区顶部（`App.tsx` 中渲染，`styles.css` 里 5 条 `.driveState*` 规则） |
| 出现时机 | 任务处于 `paused`（用户主动暂停 **或** AI 主动求助） |
| ★ 关键约束 | **两者都落在 `phase='paused'`，必须靠 `pausedBy` 区分颜色/图标/文案** —— 这是核心可辨识度：用户主动暂停 ≠ AI 在等你。**不许**只看 phase 上样式 |
| 现有类名 | `.driveState`（`.driveState--agent` / `--user` / `--none` 三条在 CSS 里，但**源码里没用到** → 是历史残留，设计时可重新定义） |
| 需要你定 | 条高、左侧图标（暂停⏸ vs 求助🆘）、两种状态的色（不能用同一色系） |

## 2. 待确认黄条（P0 确认卡）｜ `.loopGone`

| 项 | 内容 |
|---|---|
| 位置 | 中列舞台顶部（`App.tsx:3327` 附近） |
| 出现时机 | 「这一轮的上下文没了」—— 循环丢失，用户必须选一次 |
| 两颗按钮 | `重新开始`（**带代价**，现在加粗描边）/ `算了`（普通按钮） |
| 现有样式 | 红棕底 `#fdecea` + 实心边框 `#b34a2e`；**刻意不用警告黄**（黄色已被 `.driveBar` 占用） |
| ★ 关键约束 | 「重新开始」是**有代价**的那个选择，视觉上必须与「算了」区分开（现在只有加粗描边这一条差异） |
| 需要你定 | 这张卡要不要做成 modal 级的强调；两颗按钮的主次关系怎么做 |

## 3. 任务卡 + 任务详情 ｜ `#taskDetail` / `.workbenchNav__badge`

| 项 | 内容 |
|---|---|
| 位置 | 任务卡在右列聊天流里；详情浮层 `#taskDetail`；顶栏有徽标（活页数）与「驾驶中」圆点（`workbenchNav__badge` / `workbenchNav__driving`） |
| 状态机 | `idle / running / paused / …`（`TaskState`），切换由后端推 |
| 详情内容 | 名称、进度、大纲（多行）、摘要（可折叠）、文档备注输入（`docNote`） |
| 现有类名 | `.taskCard*` / `.taskSummary` / `.guide__table`（详情表用的是引导卡那套表格样式） |
| ★ 关键约束 | 任务**长什么样**必须一眼能读出来（AI 在替我做哪件事），不能只有一行标题 |
| 需要你定 | 卡片在气泡流里的身份（是气泡？是系统条？）；详情是浮层还是抽屉；顶栏徽标要不要保留 |

## 4. 头像状态圈 ｜ `.contact` / `.avatar`

| 项 | 内容 |
|---|---|
| 位置 | 左栏每一行智能体（`.contact` 行 + `.avatar` / `.avatar__face`） |
| 状态来源 | `agentStates`（服务端 `ConversationStateView` + `AgentView.status`） |
| 五种状态 | `idle` / `thinking` / `working` / `waiting` / `blocked`（**注意**：`blocked` 表示"被别的活占着"，与 `busy` 不是一回事 —— 这条语义在批次 J 的 @点名里踩过） |
| ★ 关键约束 | 设计基准的头像是**联系人**头像（静态图 + 渐变兜底）；这里要加**状态语义**，不能只做一个小圆点贴上去 —— 现有设计里已有「未读/在线」的视觉语汇，最好复用 |
| 需要你定 | 状态圈位置（右下角？外环？）、五种状态的颜色/动效、`blocked` 与 `waiting` 怎么区分（都是"没在动"） |

## 5. 四件共用的「颜色语义」建议（供你参考，不是替你定）

现在代码里已经存在的语义色（都在 `styles.css`，共 9 个 token）：
`--bg` `--panel` `--sidebar` `--border` `--text` `--text-weak` `--accent` `--primary` `--pending`
—— 其中 **`--pending`（待确认）已经存在**，说明设计意图里本来就有"待办/等待"这一档。

建议四件共用一张表（**你定值，我在 M1' 令牌层落地**）：

| 语义 | 用在 | 现有色（供参考） |
|---|---|---|
| 运行中（AI 在动） | 状态条 / 头像圈 / 任务卡 | 蓝（`--accent`） |
| 等你（要你决定） | 状态条 / 黄条 / 任务卡 | 黄（`--pending`）或红棕（`.loopGone` 现用） |
| 出事了（丢了/失败） | 黄条 | 红棕 |
| 空闲 | 头像圈 | 灰（`--text-weak`） |

1. 你给这四件的**形态 + 色板 + 文案表**（不需要 HTML/CSS，草图/截图/PNG 都行）；

   可以并行安排。
