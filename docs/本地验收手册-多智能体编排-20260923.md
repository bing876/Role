## 0. 先决条件

```bash
git fetch origin arena/01a0cab3-role
git checkout arena/01a0cab3-role
npm install
npm run build -w @ai-workbench/shared
```

## 1. ⚠️ 最容易踩的坑：提示词必须能「发车」

编排（`spawn_workers` / `delegate`）**只在任务模式里存在**。普通聊天那条路只有 `web_search`。

判定在 `apps/server/src/routes/chat.ts:339-372`。**没有打开页面时，只有强动作词才进任务模式**：

```
打开 访问 浏览 点击 填 输入 登录 注册 下单 买 购 订 选 抓取 整理 分析 诊断 爬取 刷新 滚动 关闭 切换
```

而 `搜 / 查 / 看` 是**弱动作词** —— 单独出现会走普通聊天，**编排不会触发**。

| 你输入 | 结果 |
| --- | --- |
| ❌ 帮我查一下三家竞品的定价 | 走普通聊天，只有 web_search，**不会派临时工** |
| ✅ **整理**一下三家竞品的定价 | 进任务模式，能派临时工 |
| ✅ **分析**这三家的定价策略 | 进任务模式 |
| ✅ 任何带 `https://` 的 | 进任务模式 |

下面所有测试提示词都已经带了强动作词，可以直接抄。

## 2. 准备：建两个智能体

委派需要**同一个项目里至少两个智能体**。在界面里：

1. 建一个项目（会自动带一只「母鸡」）
2. 再加一个智能体，**职责写清楚**（比如「资料员：查资料、写要点」）

职责（persona.duty）会进模型看到的同事名单，写得越清楚，模型越知道该委派给谁。

## 3. 测试一：临时工并行

**输入：**

```
整理一下这三家公司的最新定价，分别查：字节跳动、腾讯、阿里巴巴。每家给我价格区间和定位。
```

**该看到：**

- 服务端日志出现 `[orc] job=... 派出 3 个临时工（并发 3，单个 120s / 整批 180s，搜索=...）`
- 界面这一路挂起，显示「等临时工交活」之类的话
- 结果回来后自动续跑，给出三家的对比

**验证「真的并行了」**：看日志里三个临时工的时间戳是否重叠。串行会有明显的先后间隔。

**验证「临时工不撒谎」**：如果没配 `TAVILY_API_KEY`，汇报里应该如实说「没查到」，
而不是编一个看起来像真的的链接 —— `parseReport` 会丢掉不是真搜索返回过的网址。

## 4. 测试二：智能体间委派 + 内部频道

**输入**（对着智能体 A 说，让它把活交给 B）：

```
这件事更适合资料员来做：整理一下国内三家主流云厂商的对象存储定价，交给它去查，我要三个要点。
```

**该看到：**

- 日志 `[orc] 委派 1：「A」→「B」（子循环 loop_xxx，链深 1/2，超时 600s）`
- 界面这一路挂起，说明「已交给 B，最多 10 分钟」
- 顶栏点 **🗂 内部频道** → 能看到这条频道的完整对话：
  - `派活`（A 给 B 的任务书）
  - `过程`（B 走到第几步、干了什么）
  - `交活`（B 的结论）
- 下面的「这条频道上的委派」显示状态 **已完成** + 结论 + 要点提纲

**验证「防死循环」**：在 B 还没交活的时候，再让 A 委派 B 一次 ——
应该被**当场拒绝**，频道里留一条 `系统` 痕，写明「对方手上已经有在处理的委派了」。

## 5. 测试三：10 分钟超时熔断

这是你最该亲眼验的一条（要求 3b）。默认 10 分钟太久，先改短：

在 `apps/server/.env` 里加：

```
DELEGATE_TIMEOUT_MS=60000
```

（60000 = 1 分钟，这是允许的**最小值**，再小会被夹回来。改完重启服务端。）

**输入**（派一件一分钟内做不完的活）：

```
交给资料员：整理全球前二十家云厂商的完整定价表，每家都要列出所有产品线。
```

**该看到（到点时）：**

- 频道里出现 `系统` 消息：「超过 1 分钟没有做完，这次委派按超时熔断处理」
- 委派状态变成 **超时未完成**（红色，不是绿色）
- A 收到的回执如实说「**暂未完成**」，**不会**把 B 没做完的东西当成结论交上来
- A 能接着往下走（不卡死）

**关键**：状态必须是「超时未完成」而不是「已完成」。如果显示已完成，那就是 bug，告诉我。

## 6. 测试四：只读性（安全）

打开「🗂 内部频道」面板，确认：

- 面板里**没有任何输入框** —— 你没法替智能体发消息
- 按钮只有「刷新」和「关闭」，加上左边的频道列表项

这不是风格偏好：内部频道是智能体之间的交流，用户是**读者**。
服务端那边也只有 GET 接口，没有写接口 —— 前后端一致。

## 7. 出问题看哪里

服务端日志里 `[orc]` 开头的行是编排的全部动作轨迹：

```
[orc] 已注册 web_search / spawn_workers / delegate —— 委派超时 600s，...
[orc] job=xxx 派出 3 个临时工（并发 3，...）
[orc] 委派 1：「小助」→「母鸡」（子循环 loop_xxx，链深 1/2，超时 600s）
[orc] 循环 loop_xxx 被停（user_stop），级联取消 1 个后台子任务
```

`GET http://127.0.0.1:8787/health` 里有：

```json
{ "jobs": {...}, "subLoops": 0, "orchestration": "on", "delegateTimeoutMs": 600000 }
```

`jobs.live` 一直不为 0 而 `subLoops` 是 0 → 有子任务没收尾，该查熔断。

## 9. 我验不了的（所以得靠你）

沙箱里没有显示器、没有 Electron-Chromium 二进制，所以：

- **界面的像素观感、暗色模式、窄栏折行没验过**。逻辑用 jsdom 渲染真组件验了（11 条断言），但好不好看得你眼睛看。
