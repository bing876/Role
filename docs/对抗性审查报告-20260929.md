## 一、修掉的三个真漏洞（本轮已落盘 + 已入 CI）

### 漏洞 1 · CORS 回显任意来源

| 项 | 内容 |
|---|---|
| 位置 | `apps/server/src/index.ts`（原 `cors({ origin: true })`） |
| 出事方式 | `origin: true` 的含义是"**请求带什么 Origin，我就回显什么**"。等于对浏览器宣布：任何网页都可以读我的响应。 |
| 谁能触发 | **用户自己浏览器里的任意网页**。服务只听 `127.0.0.1` 只挡住"从外面连进来"，挡不住本机浏览器主动来打 `127.0.0.1:8787` —— 那条路 CORS 是全放的。 |
| 后果 | 任意网页能读用户的数据（会话 token、聊天记录、记忆）。 |
| 修法 | 白名单，只放三种：`null`（生产安装包，`file://` 的 Origin 字面值就是 `null`）、`http://localhost:5173`、`http://127.0.0.1:5173`。无 Origin 头（桌面主进程/curl）放行。 |
| 踩到并修掉的坑 | 第一版写 `cb(new Error(...), false)` → 拒绝变成 **500**，前端看到假的"后端挂了"。必须 `cb(null, false)` 静默拒绝：服务端照常 200，只是不下发 `access-control-allow-origin` 头，**浏览器那一层才真正拦读取**。 |
| 最可能误伤的回归 | 安装包的 `Origin: null`。少了这条，登录页会被自己拦死。反证脚本专门盯它。 |

### 漏洞 2 · 无 Host 头校验（DNS rebinding）

| 项 | 内容 |
|---|---|
| 位置 | `apps/server/src/index.ts`（全仓此前零命中） |
| 出事方式 | 攻击者让 `evil.example` 解析到 `127.0.0.1`，浏览器就带着 `Host: evil.example` 打本机服务，同源策略看不出来。 |
| 为什么 CORS 修了还不够 | CORS 拦的是"**读响应**"。而对 `/auth/login/xyz` 的在线爆破，**只要 HTTP 状态码就能分辨成败**，根本不需要读响应体。 |
| 修法 | `onRequest` 钩子要求 Host 主机名 ∈ `{127.0.0.1, localhost, ::1}`，非回环回 **421**。**端口不限制**（dev 与安装包端口可能不同，收紧端口会误伤自己人）。无 Host 头放行（HTTP/1.0 / 裸 socket，不是浏览器，无 rebinding 面）。 |
| 踩到并修掉的坑 | 第一版用 `host.replace(/^\[|\]$/g,'').split(':')[0]` 解析 IPv6。`[::1]:8787` 不以 `]` 结尾，正则没剥掉括号，`split(':')[0]` 拿到 `[` → 回环地址被自己 421 掉。改成先判 `startsWith('[')` 再截到 `]`。 |
| 与谁同向 | ADR-0010「loopback 绑定」。本来就只服务本机。 |

### 漏洞 3 · `/auth/login/xyz` 无失败计数、无锁定

| 项 | 内容 |
|---|---|
| 位置 | `apps/server/src/routes/auth.ts:574` |
| 出事方式 | 此前**完全没有按账号的失败计数**。已有的 `makeIpRateLimiter`（每 IP 每分钟 20 次）对**分布式慢速试密码**没有保护力：每 IP 每分钟只发 5 次，永远碰不到 20 的线，累积起来就是无限次尝试。 |
| 附带问题 | "号不存在"本身是**免费探测口** —— 状态码与文案能区分"号不存在"和"密码错"。 |
| 修法 | 新增 `makeLoginFailLimiter`：连续失败 10 次进冷却 15 分钟；**号不存在也计数**；登录成功清零。文案继续不泄露账号存在性。 |
| 设计上避开的三件事 | ① **永不整表 clear()**（清空=把正在冷却的账号一起放掉，是绕过不是清理）；② 淘汰按条做且避开"正在冷却中"的条目（否则最旧的那条——往往正是攻击者第一个试的号——优先被踢、计数归零）；③ 冷却**只设一次不续期**（否则攻击者在冷却期内继续失败就能无限延长锁定，把防爆破变成可被利用的 DoS）。 |
| 踩到并修掉的坑 | 第一版用 `until: 0` 当"未冷却"哨兵值，又用 `v.until <= t` 判"已过期" ⇒ **每一次失败都被判成已过期，计数永远停在 1，闸形同不存在**。改成显式 `lastAt` 时间窗（`t - v.lastAt > cooldownMs` 才算新的一轮）。 |

## 四、本轮**没有**修、需要拍板的项

### 4.1 MCP 端点不拦私网 IP（信息级，非紧急）

`validateMcpEndpoint()` 只禁"非回环 + HTTP"，**不拦 `10.x` / `192.168.x` / `169.254.x`（云元数据）**。
且这是**用户自己配置**的 MCP server 地址，不是攻击者可控输入，所以定级为信息级。

> **需用户拍板**：要不要给 MCP 端点加私网 IP 段黑名单？
> 支持方：防"用户被诱导配一个指向内网的 MCP 地址"。
> 反对方：有人就是拿本机局域网里的 MCP server，一刀切会砍掉正当用法。

### 4.2 登录锁定的阈值口径（需确认）

现在：**10 次失败 → 锁 15 分钟**。
这是拍脑袋的值，没有真实数据支撑。

> **需用户拍板**：10 次 / 15 分钟合不合适？
> 提醒一个副作用：真用户连错 10 次会被锁 15 分钟。若你觉得"我绝不会连错 10 次"，可以降到 5 次。
> 我倾向**保守**：个人本地工具，攻击面小，宁可松一点别误伤自己。

### 4.3 CORS 白名单硬编码 `:5173`（需确认）

`ALLOWED_ORIGINS` 写死了 `localhost:5173` / `127.0.0.1:5173`。

> **需用户拍板**：dev 端口固定 5173 吗？
> 若哪天 Vite 换了端口（或有人用 5174），dev 会突然"连不上后端"，而且现象和"服务没起"一模一样，很难排。
> 可选改进：把 dev origin 也放行**任意 localhost 端口**（`/^http:\/\/localhost:\d+$/`）。这仍然安全（攻击者的域名不可能是 localhost），且不怕端口变动。**我倾向改成这个。**

## 六、一句话总结

三个洞都是"**本机服务被本机浏览器里的网页利用**"这一类，共同根源是：以为"只听 127.0.0.1"就等于安全。
实际上 `127.0.0.1` 对用户浏览器里的任意网页是**敞开的** —— 那条路不走网络边界，走 CORS/同源策略。
现在三层都堵上了：CORS 白名单（挡读响应）+ Host 回环校验（挡 DNS rebinding）+ 按账号失败锁定（挡在线爆破）。

## 七、`index.html` 无 CSP：查过了，**决定暂不修**（附随时可启用的方案）

接手报告把这条列为"仍未修的第 4 个洞"。本轮查完，结论是**先不修** —— 不是遗漏，是这一步的风险在本环境**无法验证**：

1. **沙箱里没有真浏览器**（无 Playwright/Puppeteer；`verify:electron` 头注释明确写"沙箱内，不拉 electron 二进制"）。现有 UI 验收跑在 jsdom 上，而 **jsdom 不执行 CSP**。
   ⇒ CSP 写错的话，42 步验证链会**全绿**，真机一开就白屏。这是最坏的失败形态。
2. **本产品核心是内嵌 `<webview>` 显示真实网页。** CSP 的 `frame-src`/`default-src` 与 Electron `<webview>` 的相互作用我在此无法验证。写错 = 浏览器整列空白 = 核心功能死。
3. **渲染层其实已经硬化得很好**（2026-09-29 实测）：
   - `apps/desktop/src` 全仓 **零** `dangerouslySetInnerHTML`、**零** `.innerHTML`（`MarkdownText.tsx` 是手写极简渲染器，头注释明说"零依赖、零 dangerouslySetInnerHTML"）
   - `main.ts` webPreferences：`contextIsolation: true` / `nodeIntegration: false` / `sandbox: true` / `webSecurity: true`

⇒ CSP 在这里是**纵深防御**，不是堵漏。为一个无法验证的锦上添花去冒核心功能白屏的风险，不划算。

### 但已经铺好了零风险的路

新增 `scripts/verify/csp-conformance.mts`（已入主链）。它现在跑是"无 CSP → 跳过"，一旦 `index.html` 出现 CSP meta 就开始把关，而且**专门盯 jsdom 抓不到的那个盲区**：

| 检查 | 抓什么 |
|---|---|
| ① 构建产物逐个资源对账 | CSP 拦掉了 `dist/` 里任何一个 script/style/font → 红（= 真机白屏，jsdom 抓不到） |
| ② 远程 script-src / style-src | 放行 `https:` 之类 → 红（把洞又挖开） |
| ③ `object-src 'none'` + `base-uri` | 缺一个 → 红（这两个几乎零误伤风险） |

三条反证都真的跑过、确认会红：

| 塞什么 CSP | 怎么红 |
|---|---|
| `script-src … https:` | `script-src 放行了远程来源（https:）` |
| `script-src 'unsafe-inline'`（不放行 `./assets/*.js`） | `CSP 拦掉了构建产物里的 script：./assets/index-*.js` |

（写这个脚本时还踩了一个自己的坑：CSP 值里全是单引号关键字（`'self'`/`'unsafe-inline'`），用 `[^"']*` 提取属性值会在第一个单引号处截断，把**正确的 CSP 误判成"拦掉了 script"**。已改成先试双引号界定符。）

### 要启用时，把这段粘进 `apps/desktop/index.html` 的 `<head>`

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'self' file: data: blob: 'unsafe-inline'; script-src 'self' file: data: blob: 'unsafe-inline'; style-src 'self' file: data: blob: 'unsafe-inline'; img-src 'self' file: data: blob: https:; font-src 'self' file: data: blob:; connect-src 'self' file: data: blob: http://127.0.0.1:* http://localhost:* ws://127.0.0.1:* ws://localhost:*; object-src 'none'; base-uri 'self' file:; form-action 'none'" />
```

**每条的由来**（都是查过的，不是抄模板）：

| directive | 为什么这么写 |
|---|---|
| `script-src … 'unsafe-inline'` | 构建产物里有 1 个**内联** `<script>`（`window.onerror` 兜底），去掉就丢错误兜底 |
| `file:` | 安装包是 `file://` 页面。**`'self'` 对 `file:` origin 不可靠**，必须显式给 scheme |
| `img-src … https:` | `MarkdownText.tsx` 的 `resolveImgSrc` 放行任意 `https://` 图片（模型输出的 markdown）—— **这是本 CSP 的固有局限**：挡不住"用 `<img>` 往攻击者 URL 带数据外泄"，要堵得改渲染层 |
| `connect-src` 只给本机 | 渲染进程所有 `fetch` 都走 `API_BASE()` = `http://127.0.0.1:8787`（生产）或相对路径（dev 走 Vite 代理）。**这是本 CSP 最有价值的一条**：堵住"注入脚本把 token 发到外网" |
| `object-src 'none'` / `base-uri` | 禁 plugin 内容、禁 `<base>` 注入把相对资源指到别处。零误伤 |
| `form-action 'none'` | 本产品没有任何表单提交 |

**启用前还必须人工验三件事**（机器替代不了）：① 安装包真机打开不白屏；② dev 模式 `npm run dev` 正常（Vite HMR 的 websocket 靠 `ws://localhost:*`）；③ 浏览器列的 `<webview>` 能正常显示网页 —— 第三条正是我不敢盲改的原因。

> **需用户拍板**：要不要现在就启用？启用是"粘一行 + 人工验三件事"，我有机器证明它不会拦错任何资源（csp-conformance.mts），但**证不了它不会影响 `<webview>`**。
