# 第 27 步 · 人工介入卡片 —— 本轮补充交付（收卡后"从哪来回哪去"）

## 这轮做了什么

补上了规格里**没写、但真实用户会走到**的第 4 条路径，并修掉了它暴露的一个体验缺陷：

> 用户**自己点了「退出全屏」**（浏览器转后台，他正在聊天里看消息）→ AI 求助 →
> 卡片弹出（自动切 embed，这一步本来就对）→ 他处理完 →
> **收卡后那张页被顶成全屏**，他正在看的聊天当场被盖住，还得再点一次「退出全屏」才能回来。
>
> 等于求助这件事办完了，反而多欠用户一步操作。

**修法：从哪来回哪去。** `enterEmbed` 记下进来之前那一态，`exitEmbed` 按记录恢复；
原先在 `background` 就回 `background`，原先在 `fullscreen` 才回 `fullscreen`。

## 追加：`browser.view` 闭包快照 —— 一个**真实**但**真机 E2E 抓不到**的 bug

补上面那条路径时顺手加了一段「**切智能体往返**」真机断言，过程中翻出一个真 bug。
但它的**结论纠正过一次**，过程和结论都很值得记（第一版报告写错了，这里改正）：

### ① 真 bug（真实存在）

`App.tsx` 那个 effect 原本是 `else if (browser.view === 'embed') browser.exitEmbed()`。
`browser.view` 是**渲染时的闭包快照**，而 effect 依赖只有 `[curAgentId, helpCards]`、**不含 `view`**
⇒ 若"卡片出现（`setView('embed')`）"与"切走对话（`setCurAgentId`）"落在**同一 commit 批次之前**，
闭包里读到的仍是上一帧的 `'fullscreen'` ⇒ 那道 `if` 为假 ⇒ **`exitEmbed()` 根本没被调用**
⇒ 浏览器层停在 embed，聊天旁边露出一块**别人的网页**。
**修**：恒调 `exitEmbed()`，让内部函数式更新读最新值。

### ② ★★ 但它**不是真机 E2E 抓到的**

反证 `revert-effect-e2e.py`（注入旧写法）跑出来是 **46 PASS / 0 FAIL** —— **打不到**。
按铁律「反证 0 条变红 = 断言太弱」，必须回答"那这修复承重吗"。于是做了最小化实验
`view-race-closure.mjs`（把这条 effect 的语义搬进最小 React 组件，真实 `react-dom` 渲染）：

| 场景 | 时序 | 旧写法 | 新写法 |
| --- | --- | --- | --- |
| 1 | 跨批次（＝**常规交互**） | ✅ 正确退出 | ✅ 正确退出 |
| 2 | 同批次，但 `view` 从未是 `embed` | ✅ 不出错 | ✅ 不出错 |
| 3 | **闭包快照过期** | ❌ **停在 embed** | ✅ 正确退出 |

⇒ **① 那确实是个真 bug（场景 3 证明）；② 但常规交互走不到那个窗口（场景 1/2 都不红）。**
所以这条修复保留（无副作用、真能防极端时序），但**证据等级如实标注为"最小化实验"**，
**不能**说"已被真机反证验证"。日志：`view-race-closure.log`。

### ③ 真机那几轮 FAIL 全是**测试自己的错**

1. **JS `.click()` 不产生真实指针序列** ⇒ React 的 `onClick` 收不到 ⇒ **静默不生效**。
   判据：`layerClass` 12 次采样全 `embed`，且 `contact--on` **一直停在原智能体**。
   而且**时好时坏** —— 更早某轮"PASS"其实是页面自己变化触发收卡，属**假通过**。
   修：CDP 完整鼠标序列（`mousePressed`+`mouseReleased`）。
2. **"目标现在是当前"证明不了切过去了**：传入 id 恰好=当前项时，空操作也返 True。
   修：先读**点击前**的 `contact--on`，要求"**变了且等于目标**"。
3. **`agent2` 忘排除 `agent_id` 本身**：`addAgent()` 结尾把新智能体设为当前 ⇒
   旧逻辑把 **`agent_id`** 当成了"另一个" ⇒ 点在**它已待着的那一项**上 ⇒ 空操作 ⇒ 假红。
   修：用**集合差** `ids_ui - {agent_id}`。

修完后真机轨迹（第一次真正走到这条路径）：
```
切智能体（切到第二个）成功（3767 → 3768）
[PASS] ★ 切到别的对话 → 退出求助卡模式（不留透明层）  —— 40ms / browserLayer--bg
[PASS] ★ 切走后回到后台（记录不丢）                    —— browserLayer--bg
切智能体（切回原智能体）成功（3768 → 3767）
[PASS] ★ 切回有卡的对话 → 页面跟着回来（白框不复发）    —— 61ms / browserLayer--embed
```

### ④ 两条教训

- **"测试红了"不等于"产品坏了"** —— 动手改产品前先证明**这条路径真的被走到了**（判据 `contact--on`）。
- **"反证不红"不等于"修复没用"** —— 也可能是**测试覆盖不到那个时序**；
  这时要在**更小的层面直接把条件构造出来证明**，而不是含糊地写"已验证"或草率撤掉修复。
