### 2.4.1 这套布局的三个结构性事实（架构顾问必读）

**① 三列是「绝对定位 + 硬算 left」，不是 flex/grid。**
尽管 `.frame` 声明了 `display:flex; flex-direction:row`，
但它的三个直接子元素（`.rail` / `.sidebar` / `.main-area`）**全部是 `position:absolute`**，
`left` 分别为 `0` / `var(--rail-w)` / `calc(rail-w + sb-w)`。
flex 容器对绝对定位子元素不生效——**flex 声明实际上是死代码**。

**后果**：列宽改动需要同时改 CSS 的 `left/width` 计算**和** JS 里对应的拖拽逻辑，
两处不同步就会出现「拖拽后视觉错位」。这解释了为什么文件夹里有 121 个 `.cjs` 验证脚本。

**② 存在 `--frame-w` 的注释/令牌不一致（需实测确认）。**

| 来源 | 值 | 出现位置 |
|---|---|---|
| `:root` 令牌 | `--frame-w:1400px; --frame-h:900px` | 第 186 行 |
| `.frame` 的 `left/top` | `left:70px; top:15px`，注释写「面 1300×870 居中于 1440×900：(1440-1300)/2=70」 | 第 120 行 |
| `设计令牌.md` §0 | `1400 / 900` | 文档声明 |

**矛盾点**：`left:70px` 是按**宽度 1300** 算出来的；若 `--frame-w` 真取 1400，
则 `left` 应为 `(1440-1400)/2 = 20px`。注释与实际取值相差 100px 宽、20px 偏移。
**这属于「注释未随令牌更新」还是「实际定位偏移 bug」，需实测渲染确认**——
本报告无法通过静态阅读判定（因为 `.frame` 的 `left` 可能被后续轮次的规则覆盖）。

**⚠️ 另需注意：`.stage` 与 `.frame` 的尺寸基准不同步。**
`.stage` 用 `calc(var(--frame-w) + 140px)` = 1540 作为台面宽，
`.frame` 的 `left:70px` 只有在「台面 1440 + 框 1300」的组合下才居中；
若 `--frame-w` = 1400，则台面变 1540、框变 1400，`left:70` 就**不再是居中值**。
这是一个典型的「局部改令牌 → 全局偏移」隐患。

**③ 用 `visibility:hidden` + `:not()` 白名单做「图层模式」。**
`.frame` 上挂状态类，通过一条超长 `:not()` 白名单隐藏不需要的层：

```css
body.layers-hidden .frame > *:not(.col-divider):not(.win-controls):not(.rail):not(
   … 数十个 :not() …)
{ visibility:hidden !important; }
```

**这是设计稿「多状态演示」的核心机制**，也是 R201 报告里记录的**最大坑**：
「新节点必须加进 `body.layers-hidden` 白名单，漏加 → 新容器在 `.layers-hidden` 激活时整块消失」。

### 3.1.2 布局技术手段（如实描述）

| 层级 | 手段 | 说明 |
|---|---|---|
| 台面 → 工作台 | `position:absolute` + `transform:translate(-50%,-50%) scale(s)` | JS 按视口算缩放比，做「设计稿等比缩放预览」 |
| 工作台 → 三列 | **`position:absolute` + `left` 硬算** | rail `left:0` / sidebar `left:60px` / main-area `left:330px` |
| 工作台 → 各叠加层 | `position:absolute` + 状态类切换 `visibility` | 靠 `body.layers-hidden` + `:not()` 白名单 |
| 工作台外框 | `.frame::after` 伪元素 + `backdrop-filter:blur(40px)` | 玻璃层不占 DOM |
| 输入栏 | `left/right/bottom` 三边令牌定位 | 右侧让位 130px 给两个插件位圆 |
| 列内元素 | flex | 仅局部使用（如 `.inputbar` 内部） |
| **grid** | **仅个别卡片内部使用** | 如 R201 的 `.xyzcp-identity{ grid-template-columns:42px minmax(0,1fr) }` |

**结论**：这是一套 **「绝对定位 + 状态类」驱动的设计稿**，
而不是常规的 flex/grid 响应式布局。**它模拟的是一张固定尺寸的设计稿，
不是可响应的工作台**。所有尺寸都是硬编码像素，唯一「响应」是整体等比缩放。
