## ★★ 单文件 HTML 白屏修复 + 同步桌面（2026-09-22 06:4x）

### 症状
用户双击 `dist-single/index.html` → **白屏 / "没有加载"**。
但 headless `--dump-dom` 看 body 是渲染出来的（frame/rail/sidebar/inputbar 都在）。

### 根因（重要）
`<script type="module" crossorigin>` 在 **`file://` 协议下 origin 为 null，被 CORS 拦截 → 脚本完全不执行**。
headless 环境允许，所以 dump-dom 能渲染；**真实浏览器双击打开就白屏**。
→ 教训：**headless 能跑 ≠ 用户双击能跑**。凡是要给到用户本地打开的产物，必须额外验证 file:// 经典脚本路径。

### 修复
`vite.config.ts` 单文件模式加：
```ts
...(isSingle ? {
  target: 'es2019',
  modulePreload: false,
  rollupOptions: {
    output: { format: 'iife' as const, inlineDynamicImports: true },
  },
} : {})
```
→ 输出主 bundle 为**经典 `<script>`**（无 `type="module"`），file:// 下正常执行。

### 残留（无害）
仍有 1 个 `<script type="module" crossorigin>` —— 那是 Vite 的 **modulepreload polyfill**（`__vitePreload`），
只负责预加载 `link[rel=modulepreload]`，主 bundle 已是经典脚本，**它不执行不影响页面**。
（如需彻底消除可在 postbuild 里正则剔除，当前判定为无害、保留。）

- 控制台：仅 Edge 自身 oneauth / MSAL / 扩展噪声（已排除），**无 CORS / 无页面错误** ✓

## ★★★ 临时提交 + ref 抢救（2026-09-22 07:14~07:30）—— partial clone 离线工作法

用户要求"先把未提交改动打包成临时 commit 保命"，成功提交 `d16e3133`（父 `3c68c22`，
110 文件 = 104 新增 + 6 修改）。过程中撞上并解决了 3 个叠加故障，**方法可复用**。

### 坑 1：partial clone + autocrlf ⇒ `git add` / `git diff` / `git show` / `git write-tree` 全废
`remote.origin.promisor=true` + `partialclonefilter=blob:none`（9-21 恢复历史的副作用）
叠加 `core.autocrlf=true` ⇒ git 判断"文件变没变"时要读**旧 blob 内容** → 本地没有 → 懒加载 → 网络不通 → fatal。
- 症状极具误导性：`git status` **正常**（走 stat 缓存），但 `git diff --stat` / `git add -A` 直接 fatal
- ★★ **解法：`export GIT_NO_LAZY_FETCH=1`** —— 让 git 就地失败而不是去联网，`git add -A` 立刻恢复正常
- ★ 反例：`git -c remote.origin.promisor=false` **没用**，仍会尝试联网

### 坑 2：`git commit` 要求索引里所有 blob 都在 ⇒ 从工作区重建
索引 774 个 blob 里 **238 个缺失**，`git write-tree` 就报 `could not fetch <sha> from promisor remote`。
- ★★★ **配方**：缺失 blob 对应的都是**内容未变的文件** ⇒ 可从工作区逐字节重建，
  **且只在哈希一致时才写入**（不猜、不篡改）：
  ```sh
  h=$(git hash-object --path="$path" -- "$path")   # --path 让 CRLF 过滤生效
  [ "$h" = "$sha" ] && git hash-object -w --path="$path" -- "$path"
  ```
- ★★ 性能坑：逐个调 `git hash-object`（2 次 git 进程/文件）238 个**会超 120s 被 SIGTERM**。
  改成 **`git hash-object --stdin-paths`**（单进程批量）后秒级完成
- 脚本：`C:\Users\bing\workbuddy-ai\_recover-blobs2.sh`。结果 **238 → 0**，无一例哈希不一致
- ★ 注意：**已被修改文件的旧 blob 无法重建**（内容变了）⇒ `packages/shared/src/index.ts` 的
  旧 blob `45e025b6` 永久拿不到，它的 diff 在离线状态下就是取不出来
