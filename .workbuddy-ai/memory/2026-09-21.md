### 任务二：DeepSeek Harness（master 分支，非 main）

- ★★ **默认分支是 `master`**（按 `main` 请求 404）
- 是 pnpm monorepo，`packages/` 下 **54 个**平级子目录；三个模块**不在同一层**：
  ① 会话日志 = `packages/session/**`（19 子包）+ `packages/core/session/**`
  ② 工具流水线 = `packages/core/tools/**`
  ③ 提示词组装 = `packages/core/system-prompt/**`
- 最新发布 `0.1.6-alpha.2`（**还在 alpha**）
- **暂停/恢复的机制（任务二核心问题）**：`session-persistence/README.md` 的 "Resuming and crash recovery" ——
  日志**只追加不改写**；崩溃后**不删不改**，而是**追加"合成收尾事件"封口**：
  `interruptedTurnClosers` = 合成 `tool/result` 错误 + 任何 open `step/end` + `turn/end {interrupted}`
- ★★ 恢复时两档标记：无 durable call → `TOOL_NOT_STARTED`；有 call 无结果 → `TOOL_OUTCOME_UNKNOWN`（**不自动重试**，让模型只重试只读/幂等操作，有副作用必须核实或问用户）
- ★★ **最值得抄的单点**：`session-checkpoint-policy/README.md` 把落盘时机定在**三个语义边界**（模型请求前 / 顶层工具真正执行前 / 每个 `agent/pre-step`），且 **fail-closed**（写不成就真不放行）。
  洞察：**落盘时机跟着"不可逆边界"走，不跟着时间走。**
- ★ 它自己的诚实边界：保证的是 **"durable execution intent, not exactly-once effects"** —— **"记下了要做" ≠ "只做一次"**，真幂等要靠工具传 `exec.callId`
- 工具流水线固定六段：`tools/pre-execute` → 单调守卫 → `tools/execute` → `tools/post-execute` → `finalizeContent` → `tools/result`（只读）
  - ★ **单调守卫**：拒绝一旦发生，后续监听器**不可翻案**（对安全边界有直接价值）
  - ★ **取消分前后**：调用前 = `ABORTED_BEFORE_DISPATCH`；调用后 = 只把成功换成 `ABORTED`
  - ★ 工具失败**不结束回合**，结构化 `UNKNOWN_TOOL`
  - ★ 并发契约：**安全调用可并发；改数据的调用必须单独跑、按提交顺序**
- 提示词组装：**带 order 的片段集合**，工具 schema **是组装的一部分**；变量未解析**直接抛错**（"malformed prompt is worse than a loud failure"）；缓存策略是**能追加就不回改历史**（`systemPromptUpdate: 'in-history'`）
- ★ **不该抄**：PTC 模式（官方自承：中间值**不可从会话回放重建**且**无字节上限**，可能撑爆内存；`run_code` 每次状态全新）；呈现模式**按 agent 整体切**（同 agent 内无法按工具区分）；`timeoutMs` **只声明不生效**；`toolOrder` 配错**要等第一轮对话才报错**

### ⚠️ 两条真实损失路径（下轮修的靶子）

1. **挂起 >10 分钟再点「继续」⇒ 历史归零、从头重跑**

   → `/agent/loop/resume` 404（routes/loop.ts:323-324）

2. **点击超时被判失败 ⇒ 那一下可能已生效 ⇒ 模型再点一次**
   保护层不完整：`PAYMENT_TARGET_RE` **只在 `click` 分支**（`toolLoop.ts:776`）；`payClickGuard` 也只在 `click`（`driver.ts:1933`）
   ⇒ **`type` + `submit:true`（回车提交）只过 `typeSensitiveGuard`，不过支付闸**；
   词表（`fieldClass.ts:78` / `toolLoop.ts:723`）**不含**「发送/提交/发布/下单/预订/Send/Submit/Buy now」

### CDP 驱动 React 表单的两个要点
- 填值必须用 **native setter + `dispatchEvent(new Event('input',{bubbles:true}))`**，直接 `el.value=`
  对 React 受控组件无效
- 点击必须**完整鼠标序列**（mouseMoved → mousePressed → mouseReleased），`el.click()` 对 React 合成事件静默失效

### 登录页 DOM 速查
- 输入框：`input[0]` 手机号（maxLength 11）/ `input[1]` 验证码（maxLength 6）
- XYZ 页：`input[0]` XYZ 号 / `input[1]` 密码（type=password，要求 ≥8 位）
- 按钮：手机验证码 / XYZ号+密码 / 微信 / 获取验证码 / 登录 / ⚡快捷登录
